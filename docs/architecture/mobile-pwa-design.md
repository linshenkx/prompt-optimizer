# 移动端 PWA：安装、更新与本地状态

## 范围与边界

PWA 复用七个工作区和现有管理组件，不新增一套移动端业务实现。浏览器中的桌面布局保持原样；安装入口、离线提示和更新提示由 `packages/web` 承担，不进入 Electron 或扩展入口。

本轮先验收本地安装。固定 HTTPS 地址由用户稍后决定，不创建域名、证书或公共隧道。生产部署仍需要可信 HTTPS；普通手机访问 `http://局域网IP:18181` 继续用于开发预览，不作为长期安装地址。

## Web 外壳

- Manifest 声明稳定应用身份、启动地址、作用域、独立窗口和现有品牌图标。
- Service Worker 仅在生产 Web 构建、安全上下文中注册。开发 HMR 不注册，避免旧缓存遮蔽源码变更。
- 离线缓存只含本次构建的应用静态资源；运行时 `config.js`、模型 API、授权信息和生成数据不进入 HTTP 缓存。模型调用需要网络，离线不重放请求。
- 有更新时由用户选择更新。Web 通过 `PromptOptimizerApp` 暴露的方法确认工作区不忙并保存会话；正在生成或保存失败时保留页面，不激活更新或刷新。
- 不承诺手机后台持续运行生成请求。系统可能冻结或终止页面；保留已保存的内容，不伪造任务恢复状态。

## 数据迁移与恢复

数据属于当前浏览器的 origin（协议、主机、端口）。从局域网地址切到 localhost 或未来 HTTPS 地址不会自动共享 IndexedDB，旧地址的数据仍保留。

复用现有“数据管理”备份，在应用数据内增加版本化 `workspaceSessions`，包含七种工作区的原始稿、优化稿、模型选择、测试结果及图片引用。图片二进制仍由已有 ZIP 资源包处理，JSON 本身不携带图片文件。旧备份不含会话段时，不清空现有工作区。

导出前先保存当前会话，失败就中止，避免把过时数据标成完整备份。导入租约在七个 Store 的实际保存边界冻结新写入、等待在途保存，并通过专用许可先保存当前工作区。这样旧备份、仅收藏备份及未包含的模式也不会因刷新丢失最新草稿。

图片 GC 在整个恢复期间暂停，包括已安排的定时器和后来排队的任务。恢复按图片、收藏、应用数据与工作区的顺序提交，前置业务失败不提交工作区。成功后保持写保护直到现有刷新流程重新载入；失败释放保护。此处是共享数据完整性修复，不调整桌面组件布局。既有业务的部分导入语义仍保留，不声称收藏、模型、历史等所有数据全局原子回滚。

跨窗口补强：会话快照使用存储层的原子条件提交；安全上下文中的浏览器锁协调其他窗口保存、恢复和图片清理。成功导入时释放同源独占锁，本窗口旧 Store 的冻结保留到刷新。局域网 HTTP 无浏览器锁时保留条件提交并延后自动孤立图片清理。具体边界和回归用例见 [工作区更新与跨窗口保存边界](workspace-persistence-safety.md)。

## 私有 Magpie 预览

仅显式使用 `vite.workspace-preview.config.ts` 时启用内置测试预设。普通 Web、Electron、扩展构建不自动加入私有模型。

开发服务器和构建预览共用受限同源代理，只接受模型目录、聊天、生成图片和编辑图片端点。实际 Magpie 密钥由服务器读取和注入，不写入安装包；历史开发迁移密钥也不进入私有生产构建。客户端预设里的 `magpie-prompt-optimizer` 仅是归属标签。

更换本地 origin 后，只修正可识别且启用的本项目默认预设中的旧局域网/localhost 代理地址。用户改名、改密钥、改端点或禁用的配置保持不变。正式 HTTPS 托管时仍需部署对应的同源代理，不能只上传静态文件就声称 Magpie 已接通。

## 本地安装验收入口

开发预览继续监听 `0.0.0.0:18181`。验收用独立构建目录和临时电脑预览端口 `18182`，再通过 ADB reverse 将手机 `localhost:18181` 映射到该预览端口。手机的 localhost 是安全上下文，可测试安装和 Service Worker；Vite preview 仅用于本地验收。

该本地安装在联网调用时依赖电脑服务和 ADB 连接，不是固定 HTTPS 部署的替代品。验收须区分：Manifest 有效、浏览器具备安装资格、用户完成安装、从桌面打开独立窗口、离线重新打开、更新保存和真实模型调用。未完成的环节不能用前一环节代替。

## 验收原则

1. 真机以实际 CSS 视口为准，检查键盘、返回、长文最后一行和 A/B 并排结果，不仅看首屏截图。
2. 检查离线打开、重新加载后的会话恢复，以及更新时忙碌和保存失败分支。
3. 在独立测试数据上验证跨 origin 备份恢复及模型连接，保留原站数据。
4. 完成 Web/UI/core 的对应检查，并核查 Electron/扩展入口与普通桌面视图未引入 PWA 专用界面。
5. 将真实安装、网络调用和未完成事项分别记录在验收文档，不把单元测试或构建通过当作手机安装成功。

现有 Docker Nginx 对部分静态文件设置 `no-store`，并可启用 Basic Auth，与当前严格的公开静态资源缓存策略存在冲突。本轮不放宽认证或缓存规则；固定 HTTPS 部署、Docker 安装与离线能力需在地址确定后单独验收。详细边界见 `packages/web/PWA.md`。
