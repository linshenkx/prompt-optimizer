## 复用与改动位置

- `useWorkspaceLayout`：容器宽度、布局模式和键盘显示判断。
- `useBasicWorkspaceView`：每个基础模式独立的区域、组、折叠及阅读位置；不改会话持久化格式。
- `WorkspaceRegionSwitch`、`CompactNavigation`：区域切换与原导航入口重排。
- `AdaptiveModal`、`useCompactModalBack`：现有弹窗的窄屏外壳及返回行为。
- `InputPanel`、`PromptPanel`、`OutputDisplay`：保留业务行为，增加紧凑布局与按内容高度阅读。
- `MarkdownRenderer`：滚动容器因断点变化而替换时重新填充相同内容，避免回答变空。
- `BasicSystemWorkspace`、`BasicUserWorkspace`：接入以上布局能力，并保留既有服务、store、测试来源和模型接口。
- 收藏、历史、模型、变量、模板与数据管理继续使用原组件及数据。

### 真实页面流程

1. 两种基础模式均使用真实模型完成优化和继续优化。

7. 测试结果保存到收藏，重新打开详情能看到原测试输入和回答；应用样例恢复系统模式输入；历史恢复回原版本链。

9. 变量管理 → 添加变量 → 浏览器返回逐层关闭。功能提示词、数据管理可打开并访问原操作。

## 2026-10-20：测试结果全文阅读修正

用户试用发现，测试配置占据大半首屏，长回答在底部被截断。此前的短回答页面检查没有覆盖这一问题。

- 根因：共享移动样式中的 `.variant-results-wrap` 与工作区 scoped 桌面样式优先级相同，后加载的桌面 `flex: 1; overflow: hidden` 仍生效。外层结果容器裁剪长回答，没有把完整高度计入测试区滚动范围。
- 修正：提高移动规则的明确性，让结果按内容高度展开，由整个测试区负责纵向滚动；只读文本视图显示完整、可选择的原文，不再使用限制行数的输入框。编辑器仍使用原输入组件。
- 密度：测试组数、来源版本和模型选择通过“测试设置”展开；默认显示来源与模型摘要、运行本组和测试全部。缩短旧回答提示，移除多余卡片留白。
- 阅读：A/B 分组栏随阅读固定在顶部；切组前记录位置，防止较短结果触发浏览器高度收缩而覆盖长结果的位置。
- 验证：独立内存示例复用真实 `BasicSystemWorkspace` / `BasicUserWorkspace` 和渲染组件，不初始化应用存储、不调用模型、不改用户数据。约 2400 字、18 段回答在 393×720 系统模式和 360×640 用户模式中，渲染与文本视图均实际滚到最后一行；分组切换与切区返回保留位置。360px 展开设置无横向溢出，1280px 桌面仍显示并排结果。
- 本地回归入口位于被忽略的 `packages/web/.codex-run/reading-check.html`，通过默认端口 18181 访问；它仅用于本轮布局验收。
- 画面：`basic-mobile-implementation/04-long-answer-end.png`，明确标记示例数据，展示用户模式窄屏长回答末尾。
- 本轮工程检查：输出组件 9 项测试通过（含长文本完整显示、字面标记保留与复制回归），Markdown 响应式切换 1 项通过；UI 类型检查、受影响源码 lint 与 diff 格式检查通过。

这次检查覆盖长回答阅读，不代表手机实机软键盘等交互已验收。

## 2026-10-20：按移动端阅读重新组织测试区

用户随后指出，整页滚动仍然过长。上一节修复了裁剪，但把输入、配置和回答纵向堆叠；读到回答末尾后，设置与运行入口离开视口数千像素，不符合手机反复调整和试验的使用方式。以下布局取代上一节的“整个测试区滚动”。

- `TestWorkspaceLayout` 在手机固定分组、当前来源、模型、运行当前组及全部测试菜单，只有回答区滚动；复制、保存和文本切换工具栏随回答阅读固定。
- 共享测试输入、组数、版本及模型在全屏测试设置中修改，设置内部可切组。沿用相同输入/选择器实例和服务绑定；桌面仍内联显示配置、并排展示结果。
- 关闭设置保留阅读位置；缺少测试输入或模型时打开对应设置；成功开始新测试时返回回答并重置该组的阅读位置。
- 393×720 的隔离示例中，正文容器由约 475px 上移至约 288px，回答容器高度约 456px。滚到底后分组、设置、运行仍保持在原处。360×640 用户模式检查了四组、文本末尾和组间位置保留。
- 同时修正移动样式引用的卡片内容类名，匹配当前组件库实际的 `.n-card-content`；此前部分留白、全屏面板内容滚动、输出容器溢出规则没有生效。修复后输出工具栏可在回答区内固定。
- 本轮使用内存数据与本地模拟回调测试单组和四组运行、修改输入、查看来源、关闭/返回设置，不调用用户模型，也不读写用户会话存储。1280px 桌面检查仍有两列结果且无页面横向溢出。
- 工程检查覆盖同一输入/选择器/回答实例在设置打开、关闭、桌面切换时保留（1 项），加上输出复制/长文本和 Markdown 回归共 11 项。UI 类型及受影响源码检查通过。浏览器尺寸模拟不等于手机实机验收。
- 截图与本轮审查记录见 `mobile-focused-result` 目录及 `docs/architecture/mobile-focused-reading-audit.md`。

## 2026-10-20：优化与测试内部视图切换

本节为当前实现，替代上一节“全屏测试设置”方式。用户要求两区内部同样采用可自由切换的视图，避免配置、输入与结果堆叠。

- 优化区顶部切换“原始提示词 / 优化工作区”。输入框填满可用空间，下方保留模型、功能提示词和优化动作；优化工作区继续使用 `PromptPanel`，保留编辑、版本、继续优化和文字对照。
- 测试区顶部切换“测试配置 / 测试结果”。配置是普通工作视图；结果视图合并分组和运行操作，正文独立滚动。系统模式保留共享输入，用户模式直接测试所选提示词。
- `OptimizeWorkspaceLayout`、`TestWorkspaceLayout` 和共享切换控件只负责布局。输入、选择器和输出使用 `v-show` 保持同一实例，原会话、优化、测试和保存服务保持原绑定。
- 两种基础模式分别保留内层视图、当前组及滚动位置。新优化开始时显示工作区，新测试开始时显示结果；后续完成回调不强制导航。批量测试后续组启动不重复触发跳转。
- 输入组件的桌面折叠由外层元素控制，避免把显示指令施加到含多个根节点的组件上。窄屏选择器取消桌面 160px 最小宽度，360px 下不互相挤压。
- 本轮隔离浏览器验证：393×720 系统模式、360×640 用户模式、1280×720 桌面；原始输入和未保存工作区编辑跨内层视图、跨主区域保留；共享测试草稿保留；A/B 独立阅读位置；长回答最后一行；四组模拟运行；用户模式修改来源后运行；原文差异；桌面输入、工作区和并排结果同时显示。
