# 工作区编排整理

日期：2026-10-23。第一批范围为七个工作区的分栏交互和测试组绑定。先在基础用户模式试点，通过抽取前后的行为用例后，再推广到其余六页。后续批次在相同兼容性边界下整理来源预览、批量测试、评估动作和图片历史提交。

## 第一批：分栏和测试组绑定

- `composables/ui/useWorkspaceSplit.ts` 管理分栏草稿、指针与键盘交互和卸载清理。页面提供布局根元素、当前比例读取和提交回调。比例仍为 25%～50%，拖动期间不持久化；松开、取消或卸载时提交一次，键盘操作即时提交。会话恢复替换 layout 后仍读取新值。
- `composables/workspaces/useTestVariantBindings.ts` 仅提供 A/B/C/D 版本、模型和组数的响应式代理。页面提供读取函数和更新回调，公共模块不保存第二份配置，不负责模型回退、版本解析、请求执行或结果保存。
- 通过读取函数访问 Store，避免把初始化时的 layout、数组或数组项留在闭包内。恢复会话和更新组配置替换对象后，所有绑定仍指向当前对象。
- 多图页在 A 项缺失时的历史回退值是 `workspace`；其余六页为 `0`。通过显式选项保留该差异，不修改正常会话中 A 项的默认值。

### 第一批保留的页面责任

七个工作区的 template、style、公共组件参数、data-testid、事件名和路由不变。模型有效性与默认选择、四列宽度限制、移动端两列排版、版本解析、来源预览、优化/测试/评估、历史和会话持久化仍沿用原实现。本轮不触及 Store 格式、跨窗口保护或更新忙碌判定。

公共模块使用窄接口，不读取整套 AppServices，也不根据工作区名称分支。页面保留有实际调用用途的 A/B 别名，其他绑定直接通过按组索引的映射访问。

### 第一批行为回归

- 基础用户页面先补行为断言：拖动期间布局值不落盘、松开提交、键盘步进及边界、C/D 选择，以及恢复替换对象后的读写和实际测试请求。抽取前、试点后均执行同一用例。
- 分栏模块测试覆盖恢复值读取、取整与边界、指针松开/取消、键盘操作、卸载提交和全局事件清理。
- 使用七种真实 Pinia Store 与内存 PreferenceService，验证隐藏 C/D 不丢配置，恢复后绑定更新新数组/对象并实际持久化；另验证缺失项回退只读不写。
- Chromium 对七个实际工作区检查 1440px 桌面分栏及四列限制、2560px 四组配置、360px 两列展示与四组保留、缩减组数后恢复选择和刷新恢复。
- 结构检查比较抽取前后的七页 template/style，配合现有全量 UI 测试，避免用“函数仍在页面文件内”的源码断言替代行为验证。

本地证据在 `.codex-run/workspace-bindings-20261023/`，不提交构建、截图、测试数据库或私有配置。此轮浏览器检查与代码回归不扩展为新的真实模型调用、手机安装或部署验收。

### 第一批验证结果

- 基础用户页面抽取前的组件行为回归 2 项、试点后的组件及公共模块回归 16 项通过；最终定向复验 16 项通过。
- 全量 UI 测试 192 个文件、1246 项通过。七种 Store 的恢复、隐藏组配置及持久化行为包含在新增回归中。

- 现有 `18181` 开发体验服务、`18182` 私有生产预览和移动工作树保持原状。本轮不推送或发布。

## 后续批次的共享边界

保留七个业务工作区，不增加按模式分支的通用工作区控制器。公共模块只接受所需的读取函数、动作与回调，不接收整套 AppServices 或会话 Store，也不维护第二份业务状态。

### 来源预览：七个工作区

`useTestSourcePreview` 统一打开、关闭、选择来源与跳转前的关闭顺序。页面负责版本解析、标题、内容构造和跳转位置：

- 基础系统／用户模式使用 `live`，打开后继续反映当前会话和版本选择；桌面仍直接激活来源区域，不打开移动预览。编辑跳转到正文锚点后保留原有来源高亮。
- 两个上下文模式与三个图片模式使用 `snapshot`，打开时记录正文、是否可编辑及目标区域，后续修改不会悄悄改动已打开的预览。
- 多消息模式仍展示完整会话文本，编辑原文时展开会话管理器；其他页面分别保留输入面板和图片自动折叠状态的恢复动作。
- 历史版本的只读约束继续通过预览组件执行，公共模块不改写版本或提示词。

### 批量测试：七个工作区

`useWorkspaceTestBatch` 统一“运行中退出 → 校验所有有效组 → 准备一次 → 使用现有调度器执行 → 完成一次”的外层顺序。`runTasksWithExecutionMode` 继续决定并行或顺序执行，不新增队列、锁或调度策略。

页面保留请求校验、每组运行参数、评估清理、保存和提示策略。基础系统模式仍在同一次点击时捕获公共输入图片与各组指纹，并聚合图片供应商错误；文本模式保留 `allowParallel`。图片生成继续使用原有保存队列，文本继续在批量完成后保存一次。共享模块不吞掉执行异常，也不新增失败补偿保存。

### 评估动作：四个文本模式与文生图

`useWorkspaceEvaluationActions` 只转发单结果、对比、反馈与当前详情重评。页面仍构造评估证据、选择模型、验证可执行条件、处理对比角色，并决定指纹刷新。

基础系统模式的测试内容检查、上下文变量与多消息证据、文生图的图片证据与识图模型门槛均独立保留。四个文本页面的详情重评原本不刷新指纹，文生图会刷新；本轮保留该差异，不借抽取改变语义。图生图和多图没有因此新增结果／对比评估能力。

### 图片历史：三个图片模式

`useImageWorkspaceHistory` 共享本地编辑保存和成功历史提交后的状态应用；页面提供历史记录类型、ID 生成、图片 metadata、来源绑定与保存回调。保留当前版本的模型／模板优先级、已有链与新链分支、手动编辑清空 reasoning，以及历史提交之后才保存会话的顺序。

历史写入失败不应用成功状态；历史已提交但会话保存失败时，继续沿用原有 warning 和刷新提示策略。生成测试的排队保存不并入历史提交保存。

优化／迭代的完整生命周期继续独立：三个模式在入口校验、`nextTick`、历史错误传播、刷新事件和成功提示位置上有实际差异，多图还保留一次额外的即时保存。统一这些整段流程需要多个模式开关且容易改变行为，因此本轮只抽取明确相同的提交动作。请求构造、图片顺序、流式 token／reasoning 与错误回退继续由各页面负责。
