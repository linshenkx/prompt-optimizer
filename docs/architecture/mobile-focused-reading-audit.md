# 移动测试区阅读与操作审查

日期：2026-10-20。范围：基础系统、基础用户模式；本地默认入口 http://127.0.0.1:18181/。

本轮依据用户实际反馈复查已实现的两区工作台，继续复用 Web 组件和服务。此前整页滚动解决了长回答裁剪，但没有解决移动端反复调整和阅读的操作距离。

> 后续更新：本文记录“全屏测试设置”的历史检查。用户随后曾批准优化与测试区内部视图切换，当时实现替换为“原始提示词 / 优化工作区”和“测试配置 / 测试结果”。该阶段规则及验证见 `mobile-two-region-design.md` 与 `mobile-basic-implementation.md` 的最后一节；本页截图和旧设置流程不代表当前界面。

## 主要发现与修正

| 严重程度 | 原行为与证据 | 本轮处理 |
| --- | --- | --- |
| P1 | 393×720 页面首屏被输入、组数、来源和模型卡片占据，正文约从 475px 开始。 | 上方只保留组、当前来源/模型与运行入口；正文容器约从 288px 开始，整个回答区约 456px 高。 |
| P1 | 示例长回答滚到底时，设置入口顶部约为 -3744px，运行入口约为 -3609px。更改设置需要长距离返回。 | 分组、设置与运行固定；正文独立滚动。长回答末尾仍可直接操作。 |
| P1 | 组件库当前卡片内容类名是 `.n-card-content`，部分移动 CSS 仍匹配 `.n-card__content`，容器溢出和间距规则未生效。 | 共享移动样式对齐实际 DOM，回答复制/保存工具栏可固定，面板主体可独立滚动。 |
| P2 | 展开配置占用阅读区域；设置与桌面表单若分开重建，容易丢失输入或绑定。 | 全屏设置复用同一输入和选择器实例；设置内可切组，关闭回原阅读位置。 |
| P2 | 在末尾重新测试可能停留在旧位置。 | 新测试开始后回到该组回答开头；普通查看、切组和关闭设置仍保留各组位置。 |

## 三步体验

1. 进入“测试”，切换 A/B；上方始终能辨认当前组、来源和模型。
2. 点击右上设置，修改共享测试输入、组数、当前组的版本和模型；可以在设置内连续切组。返回回答保持位置，开始测试返回新回答开头。
3. 滚到回答末尾，直接切组、重新测试、复制或保存；无需滚回整个页面顶部。

## 验证

- 隔离内存示例使用实际 Basic 工作区和输出组件，约 2400 字、18 段回答。未初始化用户应用存储，模型调用替换为明确标注的本地模拟回调。
- 系统模式 393×720：渲染全文到底；修改共享输入后返回末尾；重新测试收到修改后的输入并回到新回答开头；设置内切到 D 后测试全部，执行四组并返回 D。
- 用户模式 360×640：渲染与文本全文到底；A→B→A 保留阅读位置；四组设置可操作；测试全部执行四组并返回回答。
- 来源全文与浏览器返回正常关闭查看面板；原“优化 / 测试”两个区域保持可自由切换。
- 1280px 桌面仍内联显示配置和两列回答，文档宽度等于视口宽度。真实默认应用入口已接入新布局，检查时没有 error 日志。
- 单元回归 11 项通过：同一组件实例在设置开关与桌面切换间保留、输出复制/长文本、Markdown 响应式切换。布局实例测试在最终结构修改后再次通过。UI 类型、受影响源码 lint、diff 格式检查通过。

## 五项审查结论

| 维度 | 本轮结论 |
| --- | --- |
| 信息结构 | 保留两个一级区域；测试设置是当前区域内的覆盖面板。 |
| 操作连续性 | 阅读、切组、设置和重新测试形成短路径，配置与阅读位置保留。 |
| 信息密度 | 阅读首屏约增加 187px；长回答不再把常用操作推离屏幕。 |
| 组件与数据一致性 | 复用现有业务组件和绑定；桌面布局继续成立，无第二套移动数据。 |
| 可访问性与设备表现 | 主要设置/运行入口按 44px 触控尺寸处理；本轮是浏览器尺寸模拟与自动检查，未完成真实手机键盘、读屏、安全区验收。 |
