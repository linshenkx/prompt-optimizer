## 2. 场景一：同一收藏版本、同一变量输入比较两个模型

**用户目标**：“用收藏里的工单摘要提示词和这条工单，比较我已配置的两个模型，保存结果供我在界面判断。”

输入为选定数据源、一个收藏的确定资产版本、一组变量值、两个已配置且可用的模型，以及关注点“事实准确、按要求输出、信息完整”。已有资产包括收藏版本、变量定义／示例、模型配置；不要求用户重新导入到另一套实验数据。评估模型可选，不能擅用第三个模型。

| 步骤与所需产品能力 | MCP／共用服务责任 | UI 责任 | Skill 责任及人工判断 |
| --- | --- | --- | --- |
| 1. 选择数据源、检索收藏版本与可用模型 | 提供安全摘要及选中资产详情，校验来源和可用性 | 展示来源、版本与模型配置入口 | 把自然语言目标落实为明确选择；同名、多来源等歧义由用户决定 |
| 2. 准备并校验一次比较 | 按现有规则合并变量、解析版本、构造消息；冻结两组共同输入及各模型配置；缺项在任何组调用前返回 | 可查看渲染后的输入、变量来源、组配置和预计调用范围 | 解释缺项，只补用户给出的值；不得猜测缺失业务事实或替换不可用模型 |
| 3. 运行两组测试并获取状态／取消 | 从已准备快照执行；沿用现有调度／模型通道；分别记录成功、失败、取消和输出 | 显示进度、两列结果、局部失败与取消状态 | 按已授权范围启动和跟踪；不因超时自动重试全部组或另换模型 |
| 4. 查看证据，按需评估 | 从完成的执行快照组装已有评估能力；返回判断与证据来源；评估单独标明模型和状态 | 展示原输出、评分／建议、比较角色及失效状态 | 解释两模型差异；用户判断事实是否准确及哪些差异影响业务；无评估模型时保留人工比较闭环 |
| 5. 保存并在产品中查看 | 保存比较组、快照、结果与已有评估的关联；返回稳定引用及产品可识别的查看目标 | 打开指定比较结果，显示来源；有未保存编辑或写入冲突时按现有规则处理 | 给出可查看的结果引用；未确认保存成功不能声称已存入产品 |
| 6. 决定下一步 | 只读取已保存证据，不自动改写收藏或模型配置 | 供用户逐项核验并选择后续动作 | 汇总适用范围与待验证问题；一次样本不推出模型总体排名，用户决定采纳或进入场景二 |

输出是一组可重新查看的真实产品比较结果：相同输入、两个模型的实际执行记录、可选评估和有证据的解释。保存比较记录不等于把某个模型设成默认模型，也不隐含更新收藏。

### 场景一与已接受合同 v0.2 的接续

依据为提交 `34898b04d07cb2abf656f13117cf22d5802f7d99` 中的 `docs/architecture/mcp-capability-contract.md`。以下收敛前文的首版语义：**合同设计已接受，实际 MCP 工具注册及生产能力尚未实现；表中名称仅为合同语义操作，不是可用工具调用。** 正式 `SKILL.md` 继续等待真实可发现接口及对应产品能力落地，不根据本文编造调用。

| 场景一步骤 | 合同语义操作 | 接续边界 |
| --- | --- | --- |
| 1. 选择来源、收藏版本和两模型 | `sources.list`、`sources.open`、`assets.list`、`assets.getVersion`、`models.list` | 首版限定 `pro-variable` 文本资产具体版本及两个已保存、启用的模型配置，不接受动态版本别名或请求级改参。每步绑定有效 `connectionId` 和同一来源；读取按既有授权选择访问级别，保存／删除需要 `save` 权限 |
| 2. 公平准备与预览 | `tests.prepare` | 同时验证资产／模型 revision、变量与两候选，冻结一次编译后的消息及配置，返回 `preparedId`、`previewRevision`、稳定 `comparisonId/runId`。客户端声明参数与实际请求参数证据分开；未公开参数只列遗漏情况，不输出凭据，也不把未知默认值当作已生效值 |
| 3. 执行、查询和取消 | `tests.execute`、`runs.get`、`runs.cancel` | 执行前重验来源 epoch 和实体 revision，过期需重新准备；开始后的 UI 编辑不改变本轮。查询／取消限原连接，保留逐组终态及 partial 输出；同准备态不重复计费执行，断连不自动重放 |
| 4. 可选模型评估 | `evaluations.prepareCompare`、`evaluations.execute` | 仅同来源、同准备组的两个成功快照可评估；明确选择评估模型，冻结证据、模型及模板。首版为一次 generic compare；无评估仍可人工比较，`patchPlan` 只作建议 |
| 5. 保存完整比较并查看 | `comparisons.save`、`comparisons.list`、`comparisons.get` | 两组及所选评估全部终止后保存整组，成功／失败／取消与 partial 原样保留；可选评估先于不可变记录保存。稳定 ID／saveKey 去重；`viewTarget` 是语义定位对象，尚无可用深链接。产品变量页“已保存比较”只读 drawer 按 ID 重新读取（`reload-required`），实际渲染该记录才算查看通过，不替换工作稿或切换收藏版本 |
| 6. 人工判断、按需管理结果与结束连接 | `comparisons.get`；仅显式删除时使用 `comparisons.delete`；结束时 `sources.close` | 判断限定于已保存证据。删除只针对指定比较并校验 `expectedRevision`，不改收藏、模型、工作区或其他比较；保留最小删除／去重标识，迟到保存不能复活。关闭连接释放其执行和准备资源，不关闭产品页面或共享服务 |

来源／页面边界按合同区分 `sourceEpoch`、`pageInstanceId` 与 `connectionGeneration`：Chrome 绑定选定页面及代次，同 origin 多页不能按最近活动页替换执行者；失联后旧句柄失效，不自动切源。重连使用新连接，历史来源证据不授予访问权；保存应答丢失时，明确选回同一数据源后先按 `comparisonId` 核对，不能据此重发模型请求。

合同已解决前文的两个接入缺口：比较评估使用 core generic 的 `custom` 快照并保留外层资产版本引用，`target.workspacePrompt` 仅承载选中原文，不创建工作稿、不伪造 workspace 来源；完整比较使用新增窄记录及只读查看入口，不向当前 session／Arena 写入，也不以收藏示例替代。记录纳入现有 DataManager；首次读取空列表不初始化业务数据。与场景一及已确认首版范围无设计冲突，候选写入和四位置复测继续留到下一步。

## 3. 场景二：依据比较结果调整提示词，再做受控复测

**用户目标**：“刚才的结果可能把‘计划完成’写成‘已经完成’，针对这个问题改一版，再用同样的两个模型和输入比较。”

输入为场景一的已保存比较引用、用户指出的缺陷与接受标准。已有资产为原收藏版本、执行快照、输出和可选评估；候选提示词沿用产品工作稿／版本机制，不覆盖原版本。

| 步骤与所需产品能力 | MCP／共用服务责任 | UI 责任 | Skill 责任及人工判断 |
| --- | --- | --- | --- |
| 1. 读取基线及比较证据 | 读取原始输入、各组输出、参数和评估；标记旧记录缺少的执行信息 | 展示原文及结果来源 | 定位问题对应的事实与输出，不把评估意见直接当成事实 |
| 2. 形成一份候选修改 | 若调用现有迭代／评估驱动改写，复用其校验与目标约束；返回候选及来源 | 展示差异，保留可编辑目标和原版 | 可由 Skill 起草简单修改，也可调用产品改写；说明改动意图，由用户判断是否符合业务要求 |
| 3. 保存候选并准备复测 | 通过产品写入能力保存工作稿或新版本、检查并发基线；用相同变量与两个模型的原运行配置准备 | 显示版本关系、冲突与复测组；人工编辑后重新校验 | 用户已经授权改写复测时按范围执行；否则停在可审查候选，不要求逐个工具重复确认 |
| 4. 执行并比较四个位置 | 组织“原版×模型甲／乙、候选×模型甲／乙”的关联结果；仅在输入、原版及模型配置完整匹配时复用原结果，否则说明差异并重新准备 | 允许逐模型查看原版与候选，再横向看两模型 | 不同时改提示词、输入和模型参数；单独列出修改收益、退化和未解决问题 |
| 5. 保存复测与决定采纳 | 保存候选、复测、基线和评估的关联；不把记录保存自动升级为收藏当前版本切换 | 展示两轮证据，处理版本采纳与冲突 | 用户判断修正是否过拟合当前样本、是否采纳；无明确继续指令时本轮结束 |

复用原输出表示复用那次观测，不代表重新执行或消除随机性；无法恢复原模型运行配置时，新的调用应标为新条件，不能宣称只改变了提示词。项目说明（包括 projectbrief/v1）可以作为提示词正文、变量或既有上下文输入，不引入项目导入器、任务树或批量优化平台。

## 4. 首版最小闭环与分工

建议首版以**桌面一个明确数据源、一个确定收藏版本、一组变量、两个已配置文本模型、一次比较保存与界面查看**为交付单位。模型评估可选，人工判断必须可完成；Chrome 接通后复用同一语义流程，数据源身份和可用性仍由连接层负责。

最小闭环不是“返回两段文本”：必须可在产品中打开指定已保存比较，核对输入、模型运行信息与结果，失败／取消也有准确状态。实现可以复用既有会话与测试组，但合同必须说清其可寻址性、保留范围和被后续测试替换的行为；不能只交付临时聊天输出或优化历史记录。

- **UI**：编辑、配置、多列展示、人工判断、评估角色选择、失效状态与冲突提示；使用与 MCP 一致的业务准备及写入规则。
- **MCP／共用服务**：真实资产读取、准备／校验、实际执行／取消、模型运行信息、快照、可选评估、保存及查看目标；不要求 Skill 操纵内部存储键。
- **Skill**：理解目标、选择已接受能力、安排比较顺序、解释证据和提出下一轮；不能用脚本直接写数据库、偏好键或浏览器存储，也不能替代核心校验。

场景二是紧接首版的一轮扩展：候选写入与受控复测能力接好后再纳入正式 Skill；此前可给出候选，交由现有 UI 编辑／复测，不能把缺失接口包装成已自动完成。

首版非目标：通用项目管理／导入、独立实验数据集、自动批量优化、无限自迭代、多用户协作、新建服务、自动修改凭证／模型配置、绕过界面冲突处理。后续可扩展多个既有收藏示例、同模型多次采样、参数对比、多消息与图片比较；均需显式增加比较维度和实际调用范围，不倒逼首版新增这些框架。

## 5. 给 MCP 合同的必要需求

本节只约束业务行为，工具拆分、传输、状态字段和存储实现由对应设计线确定。模型调用前的准备是同一工作流的一部分；不能只给通用底层方法，再让 Skill 拼接页面规则。

| 必要能力与合同约束 | 可复用的已有部分 | 仍需新增／抽取的最小部分 |
| --- | --- | --- |
| **数据源与资产定位**：区分桌面实例及 Chrome 数据来源；每次读写／运行绑定同一来源。多来源或离线时显式选择／失败，不静默回退到空库或 MCP 内存库 | 收藏、版本、变量、模型及会话接口 | 真实数据连接、来源标识、允许操作与可用性摘要；Chrome 如何选定来源由探索线确定 |
| **公平准备**：先校验全部组，再冻结版本内容、最终消息及顺序、变量值／来源、输入附件（首版仅文本）和模型配置；后续 UI 编辑不改变本轮任何组。缺失必需变量／模型不可用时整组启动前失败 | 版本解析、模板处理、变量合并及基础校验 | 从 UI 抽取可复用的准备边界和不可变执行输入；不可照搬现有逐组临时读取状态 |
| **参数可核验**：区分用户要求、客户端归一化／适配器实际发出的参数，以及未知的服务端默认值；记录实际供应商、模型标识、配置身份和影响行为的设置，不仅是 key | 模型配置、参数 schema、LLM 及适配器参数处理 | 在实际请求边界返回可安全保存的运行摘要；冻结配置与真正执行不得脱节。不能强行给不同模型发送不支持的同名参数；不兼容需在准备时报告 |
| **执行快照**：关联来源与确定版本，同时保留实际提示词、最终消息、变量、各组安全运行摘要和结果。源收藏／模型后续被改动或删除仍能解释旧运行；快照表示可核验输入，不保证供应商结果逐字复现 | 资产版本、运行组、评估快照及请求内容已有部分信息 | 补齐完整执行证据和稳定关联，不把当前编辑器内容或配置重新读取后当历史快照 |
| **状态与取消**：运行可寻址；区分未开始、运行中、成功、失败、取消等语义并暴露逐组进度、错误和已有输出；取消不等同成功，已发往供应商的请求不承诺撤回计费 | 流式回调、AbortSignal、既有调度和输出管理 | 适合 MCP 获取与取消的运行生命周期、结束语义；连接中断后先查原运行状态，不能自动重复付费调用；不要求新增队列服务或持久后台调度 |
| **评估证据**：仅消费被选中的执行快照；保留评估模型、模板／关注点、参与组、状态与结果；未完成输出默认不进入有效比较。评估失败不能抹掉测试结果 | 单结果／generic／structured 比较、建议与补丁结构 | 从 UI 抽取评估组装；合法处理收藏版本与工作稿目标、角色门槛。纯模型比较不硬套版本改进角色；不能伪造来源来迎合旧 UI 判断 |
| **保存与查看**：写入产品真实数据，返回稳定的结果引用和 UI 可识别的查看目标；明确何时保存成功、如何再次查询、部分失败如何保留；重复保存同一运行不能制造多份业务结果 | 会话保存、测试组投影、收藏示例及并发写入保护 | 完整比较的保存／读取／定位边界，必要的最小字段及 UI 接入。打开结果不自动覆盖正在编辑的工作区；冲突返回给 UI／用户，Skill 不强写 |
| **候选写入与复测（下一步）**：候选保留原版及证据关联；检查原写入基线；复测条件与基线逐项可比，不自动采纳 | 现有工作稿、历史版本、迭代及收藏版本机制 | 有限的候选提交与关联复测入口；没有该能力前明确降级到 UI，不用通用存储写工具代替 |
| **凭证与调用范围**：模型凭证只在已有执行端使用。返回／保存的运行摘要不得包含 API key、认证头、cookie、代理密码或带令牌的 URL；端点可用安全标签表达。只读取选中资产，不把所有模型配置／变量全量输出 | 已有模型执行端与部分安全错误处理 | 对返回、错误、日志及快照采用允许输出的字段集合；准备时说明本轮模型／评估调用范围，复用既有授权，不新增逐调用确认流程 |

同一输入公平比较是“比较维度明确且其他条件固定”，并不要求不同模型拥有完全相同的内部采样机制。共同支持的显式参数可以对齐；不支持的参数、未发出的值或供应商未知默认值必须如实标明。没有可靠统计时不编造费用、token 数或延迟排名。

统筹已确认首版范围：**先完成场景一的比较、保存与产品中查看，评估可选；候选写入与四位置复测放在下一步。** 首版不自动改写收藏或切换当前版本。合同需满足上述行为要求，连接／保存方式由对应实现线确认；收到已接受的 MCP 合同后，再映射具体工具与字段、编写正式 Skill 和验证实际流程。

## 6. 接口稳定后的短业务验收样例

以下是未来实际验收的明确样本，本轮仅记录方案，未创建数据、运行假接口或调用付费模型。届时在选定产品数据源中通过正常产品入口准备一条普通收藏与其版本，不能另建 Skill 专用数据库；模型甲／乙及可选评估模型由该来源已配置模型中选择。

**收藏版本一（变量用户模式）**：

```text
将以下工单整理成三行摘要：问题、处置、后续。
工单：{{ticket}}
读者：{{audience}}
```

变量 `ticket`：`09:10 监控发现订单查询超时。09:25 回滚后恢复。根因尚未确认；计划周五前补充排查结论。`

变量 `audience`：`值班负责人`。

关注点：准确区分已经完成、尚未确认与计划事项；三行内容可读；不得补充未提供的根因。候选版本只在原文末尾增加：`区分已完成、未确认与计划事项，不要把计划写成已完成，不要推测根因。`

| 验收动作 | 业务通过条件 |
| --- | --- |
| 选定来源、收藏版本一、两模型与上述变量，先准备 | 两组渲染后的消息和变量输入一致，模型身份／参数差异可见；无未解决歧义，准备不触发模型调用 |
| 删除必需变量 `ticket` 再准备；恢复后继续 | 在两组模型调用前报告缺失，不能只运行可启动的一组；恢复值后才能执行 |
| 执行两组，期间修改 UI 中的 `audience` | 本轮两组仍使用准备时的“值班负责人”；UI 明示当前输入与旧结果不同，不能用新值解释旧结果 |
| 查看原输出并按需评估，保存比较，再从产品打开 | 能定位同一比较，核对冻结输入、模型运行信息、逐组输出和可选评估；人工逐项核验事实，不能把自动评分当作事实结论 |
| 依据证据生成候选并按同条件复测 | 若原结果已有该缺陷，核对候选是否改善；若没有，不虚构失败，作为约束增强验证。按模型分别对照原版／候选四个位置，保留两轮关联，原收藏版本仍可访问 |
| 补充检查一组取消／失败及一次写入冲突 | 中止时机允许则取消活动组，否则如实显示已完成；不得显示全组成功或自动重跑已完成组。已完成结果可保存查看；冲突不覆盖 UI 新编辑，评估不把不完整输出当正常证据 |

流程通过要求有真实产品保存与界面查看的证据；模型质量结论只限这条样本。接口尚缺的步骤记录为未覆盖，不能用伪工具、模拟返回或已存在的单元测试替代业务验收。
