# 生成输出与预览架构

## 数据与视图分离

模型增量先进入 `OutputDocument`，不逐 token 重写 Vue/Pinia 字符串。
文档使用 CodeMirror `Text` 树，最多暂存 4,096 字符或 256 个增量再合并，
保留正文、推理、原始换行和状态。每个运行有自己的取消信号；同一工作区同一槽位
开始新运行后，旧运行不能发布结果或覆盖新运行的历史绑定。

生成时只显示虚拟化、只读、不折行的源码视图。全页面共用投影队列，
每 32 ms 请求一帧，每批最多更新两个视图或消耗 4 ms；每个视图仅保留一个待更新任务。
后台、不可见、被全屏替代的内嵌视图不持续重绘。恢复时按文档当前位置补齐，
不积累逐 token 的待重放视图队列。

运行完成、失败或中止时一次性发布正文、推理和终态。原文不会被富文本降级截断。
复制沿用原有去除首尾空白的规则，读取当前文档；已终结文档不会覆盖后续手工编辑。

## 检查点与恢复

显式保存和后台检查点在捕获时物化活动文档，包括标量优化结果和各测试列。
异步图片保存期间继续到来的增量不混入已经捕获的检查点。
原有 CAS、跨窗口冲突、图片引用和备份契约继续生效。
未变化工作区跳过保存，活动文档版本变化仍会触发保存。

状态为 `streaming / complete / cancelled / capacity / failed`。
恢复到未完成的 `streaming` 检查点时标记为 `cancelled`，不假装任务仍在执行。
不完整结果保留供阅读和复制，不作为成功测试结果参与评估。

## 资源边界

| 范围 | 默认边界与行为 |
| --- | --- |
| 单工作区保存内容 | 共享 1 MiB 契约，提前预留 16 KiB 元数据空间；各并发文档共同扣减，超限中止上游并保留已接收前缀 |
| 页面活动文档 | 最多 32 个；文本、换行和文档保留量的估算总预算 8 MiB，非浏览器整个堆的硬限额 |
| Markdown / 比较 | 共用一个可终止 Worker；最多 8 个排队任务、每视图一个最新版本；启动最多 5,000 ms，启动完成后解析最多 1,500 ms，超时回退源码 |
| 富文本 | 普通 Markdown 源码 64 Ki 字符、生成宿主 HTML 256 Ki 字符、每视图估算 1,500 节点、页面合计 6,000 节点；含 HTML 的预览输入最多 1 Mi 字符，剔除 HTML 块后的 Markdown 仍受 64 Ki 字符限制；超限完整源码显示 |
| 差异计算 | 两份源码共用 64 Ki 字符；200 ms / 1,000 次编辑界限 / 300 个片段；回退同时显示两份完整源码 |
| XML | 16 Ki 字符、256 个标签起始符、32 层；拒绝 DTD/实体后转源码 |
| HTML 执行 | 完整结果在统一“预览”中就地执行；每视图最多 8 个块、页面最多 24 个；各块独立交互；切换浏览器标签保留 iframe 和交互状态；内容变化、主动退出预览或组件卸载时释放 |

普通 Markdown 渲染仍关闭原生 HTML。输出预览在 Worker 中识别闭合的 HTML/HTML5 围栏、HTML 块和完整网页，
把网页源码与宿主 Markdown 分开传输；宿主只有受限格式标签与预览占位节点，经 DOMPurify 清理后一次提交。
移除了旧的代码块占位符替换，生成代码里的 `$&`、美元加反引号等字符不会作为替换模板扩增内容。
各个 HTML 块在原位置挂载独立的原生 iframe，Markdown 前后说明与顺序保留；其他代码围栏仍显示代码。
生成中只显示原文，取消、失败或容量终态不执行未完成的 HTML。基础视图统一为“预览 / 原文”，保留已有差异对比功能。
预览允许 HTTP/HTTPS 接口和 WebSocket 连接，仍遵循浏览器正常的 CORS 与混合内容规则。
脚本在独立源中运行，无法读取主应用 DOM、存储、Cookie 或桌面桥接。

原生 iframe 的隔离、CSP 和生命周期管理不提供任意脚本的 CPU/内存硬配额。
生成的无限循环或主动大量分配内存仍属于浏览器执行环境边界，不能据此承诺任意 HTML 都不会使浏览器崩溃。

## 上游与桌面进程

OpenAI（Chat/Responses）、Anthropic、Gemini 和 Chrome 内置模型传递原生取消信号。
Chrome `promptStreaming` 的第二个参数支持 `signal`，参见
[Chrome Prompt API](https://developer.chrome.com/docs/ai/prompt-api)。
完成回调允许异步并被上游等待，避免历史写入尚未结束就把当前运行当成空闲。

Electron 仅跨 IPC 传运行 ID 和回调代理，不序列化 `AbortSignal`。
主进程按发起窗口持有控制器，支持先取消后登记、窗口销毁全量取消和幂等释放。
预加载桥在正常结束、异常和调用拒绝时清理监听器。

普通自动化上下文会强制焦点，不能据其标签切换假定产生了原生 `document.hidden`。
默认回归明确区分模拟 visibility 事件与真实 CDP 冻结。
`OUTPUT_NATIVE_TAB_TEST=1` 使用独立临时浏览器，通过公开的 `connectOverCDP({ noDefaults: true })`
连接默认上下文，保留真实可见性、后台计时器节流和严格的隐藏/恢复断言。
原生测试设置 V8 旧生代 128 MiB，实测总 JS 堆上限 224 MiB，并施加 4 倍 CPU 降速。
它不接管用户的浏览器配置，也不伪造 visibility；已实际观测原生 `hidden → visible`、
后台增量接收和返回后全文一致。强制冻结回归与原生切换回归分别验证。
4 倍 CPU 降速是低算力模拟，不等于已在低内存实体机器上验收。
单测和受控流传输不等于已对所有真实模型供应商做线上请求验收；Electron 注册表单测不等于完整桌面打包验收。

复现入口（根目录，Node 版本须满足仓库 engines）：

```powershell

$env:OUTPUT_NATIVE_TAB_TEST = '1'

Remove-Item Env:OUTPUT_NATIVE_TAB_TEST
```

## 2026-10-28 Markdown 内联网页预览

输出不再区分 Markdown 渲染与单独的网页预览入口。完成后的“预览”同时呈现 Markdown 和其中的网页块，
“原文”保留原始文本；复制不受预览的占位节点或净化结果影响。HTML 块单独计入页面预算，
不把大 SVG 展开为宿主节点，也不通过提高普通 Markdown 的预算来容纳网页。
更新网页正文时即使 Markdown 占位结构不变，也提交新的网页内容；取消任务后旧 Worker 的延迟就绪消息不能提交新任务。

内置浏览器使用独立测试标签、独立数据库、真实工作区/调度器/OutputDocument/Worker，只替换模型传输。
在 4 倍 CPU 降速下，屏障确认两路流同时进入生成，生成中零个执行 iframe，完成后共四个内联网页块。
通过真实 Tab/Enter 操作四个网页计数器，得到互不影响的 1、2、3、4；滚动及切换内置标签后状态保留，返回后仍可继续操作。
切到单列原文时仅释放该列的两个 iframe；复制得到含两个 HTML 围栏和完整末尾说明的原文，重新预览恢复该列网页。

内置浏览器会强制焦点，本轮标签切换没有观测到原生 `document.hidden`，不能替代真实后台节流验收。
内置浏览器对嵌套 iframe 的鼠标定位存在限制，本轮交互使用正常键盘导航完成，没有修改生成页面的事件处理来代替用户输入。
此前的原生后台/受限堆证据仍只适用于上文明确标注的旧版范围。

同一内置浏览器、同样 4 倍 CPU 降速下，两列各 3,000 条 SVG 路径只存在于 iframe，宿主每列只有 5 个节点，网页按钮仍能递增。
两列各 5,000 行 Markdown 超出普通富文本预算后使用虚拟原文，每列 41 个 DOM 后代；复制包含全部 5,001 行（含标题）。

## 2026-10-28 扩展端的独立预览页

扩展入口通过 `HTML_PREVIEW_HOST_KEY` 提供包内 `html-preview.html` 地址，共用 UI 不检测平台或调用 Chrome API。
Web 与桌面仍使用原有 `srcdoc`；扩展以 iframe 加载清单中 `sandbox.pages` 声明的独立页面，
使用单独的 CSP，保留主扩展页面的 `script-src 'self'`。单独的 iframe `sandbox` 属性不能代替这项清单声明。

预览页加载完成后，宿主只向对应窗口发送 HTML；预览页只接收直接父窗口的固定类型消息，
拒绝超出 1 Mi 字符预算的内容，并将原文赋给子 iframe 的 `srcdoc`。相同内容不重载，替换内容释放旧文档。
生成代码与接收消息的包内页面也隔离，不能冒充父窗口更新预览。没有从预览调用扩展 API 或访问宿主数据的消息桥。
包内页面、清单以及 Web 的资源策略由单测校验一致；正常外部数据访问仍遵守浏览器跨域规则。

既有生成中原文显示、Markdown Worker、输出容量和页面预览数量预算继续生效。
切换预览/原文、移除输出和组件卸载会释放相应上下文；页面可见性变化不重建仍存在的预览。

`pnpm test:e2e:extension` 构建并扫描实际扩展包，使用独立、无窗口的 Chromium 配置验证，已接入日常浏览器测试门禁。
覆盖 Markdown 中多个交互块、单列释放、原文复制、更新内容、全屏、脚本/模块/画布/外部接口、权限隔离、
4 倍 CPU 降速下屏障确认的两路并发生成，以及页面冻结/恢复和可见性事件。
冻结与模拟可见性事件不代表真实后台标签节流，CPU 降速不代表实际低性能硬件；iframe 也不提供任意脚本的硬内存配额。
