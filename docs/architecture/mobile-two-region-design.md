# 移动端两区工作台方案

日期：2026-10-20

状态：用户已认可两区结构及区域内部切换；基础、上下文、图像共七个工作区已接入本地实现。本文记录交互规则与复用边界；基础阶段记录见 `mobile-basic-implementation.md`，其余五个工作区的实现和验证范围见 `mobile-all-workspaces-implementation.md`。手机实机与用户体验验收仍待完成。

## 1. 已确认的方向

沿用 Prompt Optimizer 的工作方式，把现有 Web 左侧的优化区和右侧的测试区，在窄屏上改为可自由切换的两个区域。

| 区域 | 包含的内容 | 主要目的 |
| --- | --- | --- |
| 优化 | 原始提示词、优化模型和功能提示词、优化工作区、版本、继续优化、编辑、原文对照、收藏 | 把提示词改好 |
| 测试 | 测试输入、各组提示词来源和模型、运行操作、回答、保存测试样例 | 检查提示词实际表现 |

两区属于同一个工作区，共用原来的会话、版本和测试状态。用户可以先测试原始提示词，也可以编辑后直接测试，或在测试过程中回到优化区。

版本和原文对照属于优化区；A/B 回答切换属于测试区。它们不成为新的一级入口。全局功能模式仍沿用 Web 的基础、上下文和图像模式。

复用现有 Web 的业务组件和处理逻辑。新增内容集中在布局容器、区域切换、窄屏控件排列和弹窗呈现。

## 2. 首版范围

### 2.1 首版必须完整交付

- 基础模式：系统提示词、用户提示词。
- 优化与测试两区任意切换，共享内容、版本和测试配置。
- 原始输入、首次优化、继续优化、编辑、保存修改、版本切换。
- 提示词与原始输入、上一版本的文本对照。
- 原始提示词直接测试、当前工作区和指定版本测试、不同模型测试。
- 测试组 A/B 默认保留，兼容现有 C/D 配置；各组独立选择来源和模型。
- 收藏、历史、功能提示词、模型、变量、数据管理的入口和窄屏操作闭环。
- 主题、语言、帮助、版本信息，以及当前环境已提供的工作区工具。
- 空白、运行中、失败、输入变化、模型不可用和未保存修改等状态。

### 2.2 首版不包含

- AI 评分、分析、比较评估和自动评估后改写。桌面已有评估能力继续保留，移动布局隐藏其入口；仅切换布局不得清除已有评估数据。
- 新建移动端独立应用、独立提示词数据格式或独立模型接口。
- 跨页面后台任务系统、关闭浏览器后续传、离线生成等新能力。

首版先交付基础模式和相关管理流程。随后用户要求“其他几个工作区也跟进，先总体完成”，范围扩展如下。

### 2.3 已批准的范围扩展

- 上下文模式：多消息编辑、选中消息优化、应用回会话、完整对话来源查看与测试；变量模式保留变量填写、预览、优化和测试。
- 图像模式：文生图、图生图、多图生图共用两区与内部视图切换，保留模型能力校验、参考图、版本、生成和结果操作。
- 参考图在窄屏横向排列；多图顺序增加触摸可操作的前移/后移入口。
- 上下文、工具、变量、图像模型等相关弹窗复用自适应外壳。
- AI 评估继续不在移动范围内。各模式的流程模拟验证、实际文件操作、真实模型请求和手机实机验证分别记录。

## 3. 页面骨架与响应式规则

### 3.1 窄屏骨架

顶部保持一行：左侧全局菜单，中间当前功能模式及切换入口，右侧工作区工具入口。

中间显示当前区域。底部常驻两个等宽入口“优化 / 测试”，选中状态明确，可附带运行状态小标记，不放版本、收藏或设置入口。

每个区域顶部提供独立视图切换：优化为“原始提示词 / 优化工作区”，测试为“测试配置 / 测试结果”。四个视图没有步骤依赖；切换只改变显示和滚动容器，原组件实例保持挂载。七个工作区分别记住当前区域、内部视图、测试组与阅读位置。

| 位置 | 规则 |
| --- | --- |
| 全局菜单 | 收藏、历史、功能提示词、模型、变量、数据，以及偏好和帮助 |
| 当前模式 | 显示“系统提示词 / 用户提示词”等实际模式；点击后沿用原来的分组与路由 |
| 工作区工具 | 清空内容、来源信息、Prompt Garden 等现有且当前环境启用的动作；空间不足时收入同一工具面板 |
| 底部两区切换 | 始终可切换；缺少输入或正在生成不禁用区域入口 |

### 3.2 宽度规则

正式实现采用工作区可用宽度判定布局，不使用设备型号或浏览器 UA。

- 起始阈值：工作区容器宽度小于 `1024px` 时采用两区切换；达到 `1024px` 时采用现有左右并排布局。
- 窄屏内容占满可用宽度，取消原型的 `max-width: 520px` 手机展示框。
- 并排模式继续使用现有左右比例偏好；进入窄屏时只隐藏分隔条，不改写该偏好。
- 断点变化只改变显示方式，不重建业务会话，不修改测试组数、版本、模型或运行状态。
- 初始阈值需要通过平板竖屏、横屏及桌面窄窗口校准；校准只调整布局阈值，不改变两区结构。

当前仓库的 `useResponsive.ts` 和 `useResponsiveTestLayout.ts` 使用不同的断点及 `isMobile` 定义，后者还包含“移动端关闭比较/全屏”的旧假设。此次工作区只使用一个明确的布局判定来源；不直接继承这些功能裁剪规则，也不顺带改动所有旧组件的断点。

## 4. 优化区

### 4.1 原始输入

沿用 `InputPanel`，放在“原始提示词”视图：

1. 原始提示词编辑框。
2. 优化模型和功能提示词选择；窄屏允许两列，文字空间不足时顺序换行。
3. 全宽“开始优化”按钮。

手机输入框占用当前视图的剩余高度，模型、功能提示词和优化按钮放在下方。桌面保留原有输入区折叠方式。校验通过并开始优化时显示“优化工作区”；此后用户可以自行切换，生成完成不再强制跳转。

模型和功能提示词选择继续保留进入管理器的入口。没有可用模型时，在选择位置提供“配置模型”，返回后刷新选择器；仍有效的原选择保持不变。

### 4.2 优化工作区

在“优化工作区”视图继续使用 `PromptPanel` 和 `OutputDisplay`：

- 标题与当前版本放在同一组；版本较多时提供可滚动的版本条或完整版本列表，不能撑宽整页。
- 主要动作保留“继续优化”和编辑入口；复制、收藏、全屏等按现有语义放在工具栏或更多菜单。
- 渲染、源码、差异视图沿用同一份内容。界面中“原始提示词”专指输入内容，源码视图避免仅标“原文”造成混淆。
- 手动编辑沿用现有未保存修改及“保存修改”机制，不为移动端建立第二套草稿或“预览后采用”流程。
- 切换历史版本仍表示切换工作区当前内容，与 Web 一致。

涉及覆盖未保存修改的动作统一保护，包括切换保存版本、切回 V0、历史复用、收藏应用和清空。提示在执行覆盖前出现；单纯切换优化/测试、查看来源、打开管理器不触发覆盖确认。

### 4.3 继续优化

点击“继续优化”打开窄屏全屏编辑面板，复用原来的迭代逻辑：

- 上部提供可展开的当前提示词参考。
- 中间是改进要求，保留迭代功能提示词选择。
- 底部是明确的提交操作。
- 输入校验通过后提交，关闭面板，优化区显示运行状态。
- 用户随后可以去测试区；完成时更新版本和状态，不自动把用户带回优化区。
- 请求失败时保留改进要求以便重试，避免重新输入。

### 4.4 文本对照

原文对照是优化区内部的查看方式：

- 比较对象：当前工作区内容。
- 默认基准：原始提示词；可切换为上一版本。
- “上一版本”的解析统一调用现有版本解析逻辑，展示实际解析到的版本；无更早版本时明确显示回退到原始提示词。
- 手机上采用单列行内差异或上下文差异；长文本可全屏阅读。
- 对照只读，不更改工作区内容、当前版本或测试来源。
- 退出对照返回此前的查看状态。

这属于文本差异显示，不涉及 AI 评估。

## 5. 测试区

### 5.1 系统与用户模式的区别

| 模式 | 测试输入 |
| --- | --- |
| 系统提示词 | 共享测试内容与可选图片输入放入“测试配置”视图，复用原输入组件 |
| 用户提示词 | 直接使用各组选择的提示词作为测试内容，不增加重复的“用户输入”框 |

系统模式一次“测试全部”使用同次点击时的共享输入快照，保证各组比较条件一致。

### 5.2 测试组

手机上一次显示一个测试组，通过 A/B，必要时 C/D 标签切换。每组仍包含自己的来源、模型、运行状态和回答。

根据长回答试用反馈，测试区改为固定操作、独立阅读：

- 上方固定“测试配置 / 测试结果”切换；结果视图把分组标签、“测试当前组”和“测试全部”菜单放在同一行，下一行显示当前来源和模型摘要。
- 仅回答区域纵向滚动；复制、保存和文本视图工具栏在阅读区内保持可用。
- “测试配置”是普通工作视图，包含共享输入、组数、组间切换及各组的版本和模型；不再通过全屏测试设置弹窗进入。切回结果时保留各组阅读位置，开始新测试时显示结果并回到该组新回答开头。
- 输入、选择器、输出组件保持同一实例；桌面同时内联显示配置和回答。切换视图不改动测试数据，不增加浏览器历史条目。
- 缺少测试输入或模型时显示对应配置；批量测试只在用户点击开始时切到结果，后续各组陆续开始或完成时不抢走用户当前视图。

- 默认两组，与现有会话一致：A 为原始提示词，B 为当前工作区；恢复会话时以用户原配置为准。
- 保留现有来源：原始提示词、当前工作区、上一版本、指定保存版本。动态来源显示当前实际指向，不能把“当前工作区”误说成“最新保存版本”。
- 来源和模型选择属于当前组；修改 A 不改变 B。
- 配置视图标签显示组名和简短来源；结果视图标签显示组名，完整的当前来源放在下方摘要，避免四组时挤压运行按钮。
- “测试全部”运行当前启用的组；组内保留“测试本组”。正在运行的组不得重复提交，其他组的结果仍可查看。
- 测试组设置支持现有 2/3/4 组。减少启用组数时暂时隐藏多余组，保留配置和结果；清除数据属于另外的明确操作。

**组数与列数必须分开。** 现有 `layout.testColumnCount` 同时决定启用组和显示列数，宽度变化还会把 4 改成 3。正式实现保留其旧数据可读性，先把“启用组数”作为业务配置读取，将可见列数作为布局派生值；不为此次改造强制迁移存储结构。

窄屏始终只显示当前一组；并排模式可按测试区宽度分行或减少并排列数，但不能因此减少启用组、丢掉 C/D 或改变“测试全部”的范围。桌面相应控件应表达“测试组数”，避免继续混淆。

### 5.3 来源查看与回答比较

来源标签提供“查看提示词”，打开只读查看面板，显示完整内容及实际版本。查看固定历史版本不改变当前编辑版本。

对于原始提示词和当前工作区，可从查看面板显式选择“前往编辑”，再切到优化区并定位对应输入或工作区。单纯点击来源不能只让隐藏区域闪烁，也不能隐式覆盖草稿。

回答比较采用 A/B 切换阅读：

- 每组保留自己的阅读位置和展开状态。
- 顶部保持来源、模型可识别，避免读到长回答后不知道对应哪一组。
- 不新增手机上的多列回答并排，也不默认把多组长回答全部堆叠。
- 测试结果保存继续使用现有收藏/样例功能及来源快照。

### 5.4 变化、运行与失败

| 状态 | 行为 |
| --- | --- |
| 尚未测试 | 显示来源和模型，提供测试入口 |
| 正在运行 | 当前组显示输出和状态；切区域、切组不取消请求、不重新发请求 |
| 配置或输入已变化 | 保留上次回答，明确提示“条件已变化”；重新运行前不能按新条件保存旧回答 |
| 某一组失败 | 在该组显示原因与重试入口；其他组成功结果保留 |
| 模型被删除或禁用 | 选择器显示可处理的状态，按现有模型回退规则处理并更新结果有效性 |
| 来源不存在或为空 | 采用现有解析和校验规则，标明实际来源；不能把空输入包装成成功测试 |

发起请求时固定来源、模型、共享输入及结果指纹。完成后以这份运行快照判断回答属于什么条件。期间修改其他内容不会悄悄改变正在运行的请求含义。

这次不新增独立的后台任务队列。取消能力只有接通现有请求取消链路后才能显示，不能做一个仅停止界面动画的“停止”按钮。

## 6. 原 Web 导航、管理页和弹窗

导航动作继续调用 `PromptOptimizerApp` 的现有处理函数；模式路由、管理对象和服务不另建一份。

| 原功能 | 窄屏入口与呈现 | 返回规则 |
| --- | --- | --- |
| 功能模式与子模式 | 顶部当前模式，分组列表 | 沿用实际路由；各模式会话隔离 |
| 收藏夹 | 全局菜单，沿用收藏页面 | 浏览后返回原区域；明确“使用”才应用内容 |
| 历史记录 | 全局菜单，全屏列表和详情 | 浏览不修改工作区；复用按原模式和版本链恢复 |
| 功能提示词 | 全局菜单及相关选择器的管理入口，全屏管理 | 保留入口上下文；选择模板后更新对应选择器 |
| 模型管理 | 全局菜单及模型选择器，全屏列表/编辑 | 关闭后刷新模型，保留仍有效的选择 |
| 变量管理 | 全局菜单及现有变量入口，窄屏卡片/编辑 | 复用变量存储和校验，不改变当前提示词 |
| 数据管理 | 全局菜单，全屏管理 | 原导入、导出、备份与确认流程保留 |
| 主题、语言 | 全局菜单 | 沿用当前偏好即时更新；新增文案走 i18n |
| 文档、网站、GitHub | 全局菜单中的帮助分组 | 沿用现有外链处理 |
| 版本与更新 | 全局菜单底部 | 按 Web/扩展等宿主实际能力显示 |
| 清空内容 | 工作区工具 | 保留明确的影响范围说明和确认 |
| 来源信息 | 工作区工具中的来源入口 | 可查看完整来源，不挤占内容区 |
| Prompt Garden | 工作区工具，依原环境开关显示 | 保留发现、导入使用、导入收藏的区别 |
| 保存收藏/测试样例 | 内容或回答的操作入口，复用原表单 | 保存成功回到原区域、原组；取消不丢失内容 |

### 6.1 弹窗分类

不再用一条全局 CSS 把所有弹窗都变成全屏：

- **短选择**：模式、版本、模型选择、操作菜单用适合触摸的选择面板；列表过长时可搜索、独立滚动。
- **长编辑和管理**：模型编辑、功能提示词、变量、继续优化等采用全屏面板；固定标题和操作区，主体滚动。
- **简短确认**：删除、清空、放弃未保存修改仍用紧凑确认框。
- **大段阅读**：提示词全文、差异、回答全屏共用现有输出组件。

弹层关闭后恢复原区域、测试组和触发位置。列表进入编辑后，“返回”先回到列表；表单未保存时沿用相应保护。

浏览器返回需要与现有路由协调：有编辑层时先返回上一层，有顶层管理面板时先关闭面板，无面板时才返回路由。区域切换不向浏览器历史追加条目，避免一次次后退穿过 A/B 和优化/测试切换记录。只关闭界面不应顺带清空工作区。

## 7. 复用与状态方案

### 7.1 组件职责

以下新增名称是职责建议，实施时优先合并进现有相同职责的组件。

| 层次 | 现有基础 | 正式实现内容 |
| --- | --- | --- |
| 应用壳 | `MainLayout`、`PromptOptimizerApp`、`AppCoreNav`、`AppHeaderActions` | 紧凑导航与现有全局动作共用数据和处理函数 |
| 工作区布局 | `BasicSystemWorkspace`、`BasicUserWorkspace` | 提取可复用的两区布局容器，分别接收优化区和测试区；保留原工作区业务绑定 |
| 区域切换 | 原型 `MobileRegionSwitch` | 转为普通布局组件，提供标签、运行状态、键盘与读屏支持 |
| 优化内容 | `InputPanel`、`PromptPanel`、`OutputDisplay` | 提供紧凑排列和自适应阅读能力，复用编辑、版本、迭代、差异逻辑 |
| 测试内容 | `TestInputSection`、`TestPanelVersionSelect`、`SelectWithConfig`、结果显示及保存组件 | 窄屏分组切换，宽屏按宽度排列；来源解析、请求和结果保持同一套 |
| 管理界面 | 现有模型/模板/变量/历史/数据/收藏组件 | 只按需要抽取共享表单内容与自适应外壳，不重写各自业务 |
| 业务状态 | 各模式 session store、`useBasicWorkspaceLogic`、session restore | 原始输入、工作区、版本、模型、测试配置和结果继续使用现有来源 |
| 视图状态 | 工作区级 UI 状态 | 记录当前区域、区域内部视图、当前测试组、桌面折叠和阅读位置，不复制提示词与回答 |

实现顺序先用最小布局改造证明两个基础工作区稳定，再提取已重复的布局与测试组呈现。避免为这次适配先重写所有工作区。

### 7.2 保留规则

| 状态 | 切区域/开关管理器 | 离开模式后返回 | 刷新页面 |
| --- | --- | --- | --- |
| 提示词、版本、模型、测试配置和结果 | 保留 | 按原模式 session 恢复 | 按现有持久化机制恢复 |
| 编辑中的工作区文本 | 保留 | 确保编辑缓冲进入现有草稿链路后恢复 | 与现有草稿保存语义一致 |
| 当前区域、内部视图、测试组、桌面输入折叠 | 保留 | 当前浏览器会话内按模式保留 | 当前实现不持久化视图选择，刷新后使用安全默认 |
| 渲染/源码/差异选择 | 保留 | 同一工作区内容下恢复 | 不承诺精确恢复所有临时查看状态 |
| 滚动位置 | 各区域/各组独立保留 | 内容仍对应时恢复 | 不要求恢复精确像素 |
| 运行请求 | 在原工作区继续执行 | 沿用现有路由离开策略 | 不承诺恢复网络请求 |

两区切换不重新挂载业务组件。可以用 `v-show` 或等效的保持实例方式，不同时创建两套桌面/手机编辑器。隐藏区域的尺寸变化不得触发业务配置重置。

轻量视图状态不混入历史版本内容；需要长期持久化的偏好通过已有 `PreferenceService` 及统一键定义处理，不散落新增原始 `localStorage` 读写。跨路由临时视图状态集中管理，避免在每个控件里维护不同规则。

新建或清空工作区重置视图到优化区、原始输入展开；历史复用、收藏应用等显式载入动作沿用业务路由逻辑并定位载入内容。普通管理器的关闭不触发此类重置。

## 8. 手机可用性要求

- 常用触摸入口以不小于 `44 × 44px` 的可点击区域为设计目标；通过内边距扩大触摸区域，不靠缩小字体塞下桌面工具栏。
- 正文和编辑输入以 `16px` 为基准，标签允许更小；完整名称可在选择面板或详情查看。
- 优化区和测试区各设一个主要纵向阅读滚动容器。短输入按内容增长到上限；只有长编辑器、代码块或全屏阅读内部滚动，避免卡片、结果、页面三层同时争夺滚动。
- 优化区原始输入可收起；测试输入放入设置面板，不挤压回答区。不能要求用户滚过整段回答才能修改设置或重新测试。
- 使用动态视口高度和安全区留白。底部切换条、表单提交按钮不能遮挡最后一段内容。
- 键盘打开时优先保证输入位置和当前表单操作可见；编辑状态允许暂时收起底部两区条，键盘关闭后恢复。以真实设备验证为准，不能仅按窗口变矮就误判横屏为键盘。
- 长模型名、20 个以上版本、长提示词、Markdown 表格和代码块均不能撑宽整页；必要的横向滚动限于对应内容块。
- 对比差异不能只靠颜色传达；主题、焦点、读屏名称、选中态和错误状态需一致可辨。
- 新增运行时文案使用 i18n，以 `en-US` 为 source locale，所有语言包键结构对齐；中文原型文案不直接带入运行时代码。

## 9. 原型转正式实现的差距

当前原型已证明：可以直接在真实 Basic 工作区里组织两区，无需再建一套移动端优化器。以下原型措施要在正式实现前替换或补齐：

| 原型现状 | 正式处理 |
| --- | --- |
| `VITE_MOBILE_PROTOTYPE` 控制整套手机外观 | 使用共享布局判定，原型预览入口与生产配置分离 |
| 强制手机宽度、`mp-*` 样式和残留旧布局 CSS | 删除展示框及废弃样式，形成有明确作用域的组件样式 |
| 基础模式已适配，上下文/图像进入旧工作区 | 分阶段交付，按模式记录验收范围 |
| 原型菜单单独列出动作、使用部分全局事件/Teleport 接线 | 复用原导航定义和组件事件；需要 Teleport 时由布局容器管理稳定目标 |
| 所有弹窗统一覆盖尺寸 | 按短选择、长编辑、确认、大段阅读分类适配 |
| 特定宽度条件被演示开关绕过 | 正式分离启用组数和可见列数，修复缩放写回配置的问题 |
| 版本切换已有部分未保存检查，V0 等入口未统一 | 统一所有覆盖草稿路径的保护 |
| 点击测试来源主要反馈到原区域 | 补完整只读查看与显式前往编辑流程 |
| 各模式零散存储轻量 UI 状态 | 收敛状态生命周期和重置规则 |
| 继续优化提交后清空输入 | 请求失败时保留或恢复本次改进要求 |
| 输出差异分支修复混在原型改动中 | 独立验证共享组件修复，避免夹带不可追踪的桌面行为变化 |
| 中文硬编码和本地示例模型 | 接入 i18n；演示服务与种子模型不进入生产初始化 |
| 浏览器模拟视口验证 | 补真实键盘、安全区、横竖屏和真实模型调用验证 |

原型的规则生成回答只用于验证交互，不代表真实模型质量、请求可靠性或完整业务验收。

## 10. 实施拆分

首个移动版由 A–D 共同组成；每项完成后可独立审查，不能把只完成布局的 A 当作可用版本发布。

| 顺序 | 交付内容 | 主要涉及文件/模块 | 完成条件 |
| --- | --- | --- | --- |
| A. 布局和状态基础 | 容器宽度判定、两区切换、共享组件实例、测试组数与列数分离 | `MainLayout`、两个 Basic 工作区、布局 composable、区域切换组件 | 窗口缩放、切区域均不改数据；桌面仍能正常使用 |
| B. 基础操作闭环 | 输入、编辑、版本/草稿保护、继续优化、文本对照、来源查看、测试组与结果有效性 | `InputPanel`、`PromptPanel`、输出和版本组件、`useBasicWorkspaceLogic` | 两种基础模式可完成原始测试、改写、迭代、比较、保存 |
| C. 导航和管理闭环 | 原导航映射、管理器尺寸/返回、长表单、收藏/历史应用 | `PromptOptimizerApp`、导航组件及现有各管理器 | 从手机配置模型、选功能提示词、管理内容并返回原工作区 |
| D. 正式收口 | 真实设备输入、可访问性、i18n、桌面/扩展回归、移除演示耦合 | 样式、语言包、相关测试和 Web 构建配置 | 达到下节首版验收标准，生产入口无演示注入 |
| E. 上下文（已接入） | 在相同两区容器中接入消息编辑、变量和对应测试组件 | `ContextSystemWorkspace`、`ContextUserWorkspace` 及相关组件 | 各自完整流程单独验收 |
| F. 图像（已接入） | 处理参考图、参数、生成结果与多图阅读，复用真实图像组件 | 各 `Image*Workspace` | 图片选择、生成、结果保存等流程单独验收 |

E/F 沿用“两区承载本模式编辑与验证”的组织方式，但需要依据实际消息和图片工作量补充细节；不把 Basic 的单个文本框硬套到其他模式。评估保持另立范围，后续确有需求再设计。

## 11. 验收清单

### 11.1 用户任务

1. 首次进入，配置模型和功能提示词，返回原位置，输入提示词并优化。
2. 不优化，直接到测试区测试原始提示词。
3. 优化后编辑当前工作区，立即用该草稿测试，保存版本，再测试指定版本。
4. 在优化进行中切到测试区，再返回；生成继续，完成不抢走当前区域。
5. 查看原始提示词差异、上一版本差异；退出后工作区内容和版本未被改动。
6. 输入继续优化要求，提交并离开优化区；成功有新版本，失败可保留要求重试。
7. 给 A/B 设置不同版本或不同模型，分别测试/测试全部；切换组后回答、来源和阅读状态正确。
8. 桌面配置 4 组后缩到手机，再回桌面；C/D 配置和结果均保留。
9. 测试后修改模型、提示词或共享输入，旧回答出现变化提示，保存不错误绑定新条件。
10. 从测试区打开模型管理并关闭，仍回到原组；从收藏/历史浏览返回不覆盖草稿，明确使用才应用。
11. 未保存修改时切 V0、切历史版本或应用其他内容，均有一致保护；普通两区切换不打断。
12. 保存提示词收藏和测试样例，并从原有入口重新查看。

### 11.2 显示与设备

| 场景 | 通过标准 |
| --- | --- |
| 360×640、393×852、430px 宽模拟视口 | 页面无整体横向溢出；主要动作可见可达；长文本可读 |
| 768–1024px、平板横竖屏 | 使用适当布局；不出现极窄的左右两区；跨断点不改写业务状态 |
| 1280px、1440px 桌面 | 原并排布局、分隔条、多测试组和管理器正常 |
| iOS Safari 与 Android Chrome 实机 | 键盘、滚动、粘贴、选择文字、安全区、返回、文件选择可用 |
| 明/暗主题、中文/英文 | 文案、按钮、选中态和差异可辨；英文长标签不挤出页面 |
| 无模型、长模型名、很多版本、长回答 | 选择/查看仍可完成；没有不可见的确认按钮 |

上述实机项必须记录实际设备与浏览器；桌面模拟视口通过不能代替实机通过。

### 11.3 工程验证

- 单元验证集中在真正有风险的规则：断点不改启用组、来源解析、结果过期、草稿覆盖保护和旧会话恢复。
- E2E 覆盖关键跨区域流程、管理器返回和多测试组保留；沿用仓库按模式划分的稳定 `data-testid`，不依赖中文按钮文本。
- 执行受影响 UI 的类型检查、lint、语言键一致性和运行时中文检查。
- 共享组件改动执行 Web 和扩展的相应类型/构建检查及桌面关键路径回归；沿用项目现有测试入口，不为纯布局增加重复业务测试。
- 演示或回放验证与真实模型验证分开记录。至少用实际配置模型完成一次优化、一次继续优化和一次 A/B 测试，确认生产服务链路与结果来源正确；单次验证不代表所有供应商均通过。
