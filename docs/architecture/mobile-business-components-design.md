# 移动端业务组件设计

日期：2026-10-22。呈现层整理基线：`bcf84153`。

六类管理功能的移动呈现已实现，已完成记录范围内的开发侧验证；这不等于用户已验收，也不代表所有页面、机型及失败路径都已覆盖。架构整理见 [移动端架构评估](mobile-architecture-review.md)，已验证的操作、证据与覆盖边界见 [业务组件验收记录](mobile-business-components-acceptance.md)。

## 共同边界

- 保留现有功能入口、服务、校验、模型配置和持久化。移动布局、工具栏与交互分支显式受 compact 状态约束，桌面正常流程保持原有呈现。共享的图像保存失败修复单独说明，不将其描述为桌面行为完全不变。
- 一个宿主持有一份 controller 和草稿，桌面与移动端使用不同呈现；改变窗口尺寸不能重新加载草稿、重复发请求或丢失编辑内容。
- 各功能自行决定列表、详情、表单的合理层级，不强行套统一步骤向导。公共能力限于标题/返回、可滚动正文、键盘避让及主要操作栏。
- 次要操作进入对应条目的菜单；主要操作始终可到达。正文、表单和值优先占空间，不用放大标题或密集图标填充页面。
- Android 返回先退出当前编辑或详情，再回管理列表，最后返回原工作区；未保存内容遵循明确的保存/放弃语义。

## 各业务的移动呈现

| 功能 | 列表与定位 | 详情 / 编辑 | 主要操作与业务复用 |
| --- | --- | --- | --- |
| 模型管理 | 保留文本、图像、功能模型三个分类；紧凑行展示名称、模型/供应商与启用状态 | 点行直接进入配置，无额外只读详情页；连接信息和模型展开，高级参数/请求头折叠 | 明确的测试与保存；复制、启停、删除在条目菜单。复用文本/图像 manager 与参数编辑能力 |
| 历史记录 | 搜索与模式筛选保留在列表顶部；按优化链呈现，避免所有版本全文展开 | 进入一条链查看版本和正文，版本选择不遮挡正文；恢复前清楚标明目标工作区 | 恢复为主要动作，删除为次要动作；复用已有恢复与草稿保护 |
| 功能提示词 / 模板 | 先按用途显示当前分类及搜索结果，七种模式直接可选，不先切父级再切子级 | 详情优先展示模板正文；编辑进入独立草稿，保留预览和变量说明 | 编辑/保存为主要动作，复制、导入、迁移放入明确菜单；复用原模板服务和校验 |
| 变量管理 | 保留现有手机卡片思路，每行显示变量名和值摘要；长值不撑高整个列表 | 编辑页分别安排名称、说明、值；长文本值占主要空间 | 保存/取消固定可达；导入导出属于列表层，避免编辑弹窗内继续叠弹窗 |
| 收藏 | 复用现有列表、详情、编辑子组件；搜索和常用筛选可见，低频筛选单独展开 | 正文或图像优先，来源、标签等信息折叠；编辑与查看使用同一份条目状态 | 应用到工作区为主动作，编辑、导出、删除为条目动作；保持既有来源关联与资源处理 |
| 数据管理 | 导出、导入、远程备份、存储占用四个任务入口，避免一页堆叠所有表单 | 进入所选操作后展示其必要配置及范围；进度与错误留在当前任务 | 沿用既有恢复/清理确认，明确影响范围；切换任务保留草稿，不改变数据格式或远程协议 |

实施按模型管理 → 历史/模板 → 变量 → 收藏 → 数据管理推进。收藏的分类、标签和导入子功能也纳入本轮，避免仅改入口而保留不适合手机的内部表格。

## 已落实的架构边界

- **状态归属**：各业务宿主继续持有唯一 controller、当前条目和编辑草稿。呈现切换不重建业务服务；需要保留草稿、任务或列表位置的子树保持挂载。只读折叠信息可以按需渲染，不能为了隐藏布局而保留无内容的间距。
- **组件复用**：`common/MobileModelRow.vue` 只负责移动行呈现，业务动作和测试状态由 props、事件及 slot 提供。文本与图像能力没有被强行合并为新的模型业务类型；参数解析、供应商规则和持久化仍属于已有组件及 composable。
- **弹层契约**：`AdaptiveModal.compactClass` 是显式 opt-in，仅在 compact 时附加到弹层根节点。它解决 Teleport 后业务根类和样式定位的问题，不承担业务字段布局或草稿控制。
- **分类宿主**：`FavoriteLibraryWorkspace.vue` 的分类弹层复用既有 `AdaptiveModal`，避免内部已适配却仍套着旧 80vh 外壳。保留原属性、样式和 preset，移动端获得全屏及键盘避让，桌面沿用适配器默认呈现，不再增加另一套弹层状态。
- **样式归属**：新业务 compact 样式由所属 SFC 维护。`compact/management.css` 只保留页面与已有控件的兼容规则，旧变量行规则已删除；不要继续在公共入口追加深层覆盖来修业务表单。
- **键盘下拉菜单**：`useSelectMenuViewport` 根据 `visualViewport` 的实际可见高度、偏移和触发器位置计算方向及可滚动高度；`useCompactSelectMenu` 在同一文件中为普通表单 `NSelect` 提供绑定。菜单关闭或组件卸载后释放监听，缩放不按键盘遮挡处理。桌面不附加这些布局约束，也不关闭搜索能力。
- **供应商选择**：移动供应商菜单重选当前值时，不再次调用切换供应商的清理逻辑，保留连接、模型及凭据草稿；只有值真正变化才执行既有切换流程。该同值保护仅作用于 compact 呈现，桌面入口语义保持原样。
- **异步与退出**：移动编辑页明确处理未保存确认、重复关闭、保存失败和晚到回调。保存成功才退出；失败保留输入。模板关闭确认绑定当前编辑会话，避免旧确认关闭新草稿。

### 模型管理的具体归属

`ModelManager.vue` 持有分类和刷新关系，移动列表顶部显示标题、新增和三个分类。分类切换保留子组件及列表位置；编辑页顶部提供返回，连接与模型字段优先，高级参数和请求头折叠，底部固定测试与保存。

- `useTextModelManager` 继续负责列表、启停、克隆、连接测试、模型刷新、参数及保存。`TextModelManager.vue` 管理编辑入口与删除确认，`TextModelEditModal.vue` 管理单份编辑草稿、请求头转换及移动未保存确认。
- `useImageModelManager` 继续负责字段校验、参数合并、保存与真实图像测试。`ImageModelManager.vue` 持有逐模型测试状态和预览；移动图像编辑增加未保存确认，不另建一套图像服务。
- `ModelAdvancedSection`、`ModelParameterEditor` 复用既有参数语义，只调整 compact 呈现。功能模型保留评估、识图选择与能力过滤，以紧凑选择卡呈现。

### 共享失败路径修复

`useImageModelManager.saveConfig()` 改为返回明确的成功布尔值。存储失败时返回 `false`，编辑器保留草稿，不再因错误被内部捕获而误判成功并关闭。该修复同时影响桌面保存失败行为，桌面正常保存流程与布局未重新设计。自动化通过真实 composable 配合失败的存储边界验证此路径。

## 验收约束

真机覆盖 360×669 CSS 视口、DPR 3，以及新增的 392×769、DPR 2.75；两机键盘展开后的可见高度分别约为 299/363 和 417.8/481.8。新机键盘状态还观察到 `visualViewport.offsetTop` 为 261.09，判断控件可见性时须将元素坐标减去该偏移后与可见高度比较。另检查 393/430 宽度和桌面 1440×900。复用现有预览模型并克隆 QA 测试项，不覆盖原模型配置。

1. 列表定位 → 克隆 → 编辑名称、连接和模型 → 键盘展开时到达末尾字段与保存 → 测试成功 → 保存 → 返回工作区选用该模型 → 完成一次优化与测试。
2. 图像模型覆盖配置、真实生图与图片预览；折叠、返回、切分类不能重复触发生图。真实测试返回图片不自动等于所有图片查看和供应商选择状态都验收通过。
3. 覆盖测试失败、保存失败、继续编辑、放弃修改、Android 返回、切分类后列表位置、窗口宽窄切换与功能模型刷新。
4. 保留密钥遮罩及未修改的原值、供应商切换规则、参数合并、默认模型保护和 `modelsUpdated` 刷新链。自动化只增加这些真实风险对应的测试。

按操作闭环记录验收范围，区分真机、模拟视口和自动化测试。尚未执行的远程上传、覆盖恢复、额外机型及补充页面不由测试数量替代；具体状态随 [验收记录](mobile-business-components-acceptance.md) 更新。
