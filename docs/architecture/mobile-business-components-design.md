# 移动端业务组件设计

日期：2026-10-22。呈现层整理基线：`bcf84153`。

本文是下一阶段的具体设计与实施边界，尚未表示这些业务页面已经完成改造或手机验收。架构整理与验证见 [移动端架构评估](mobile-architecture-review.md)。

## 共同边界

- 保留现有功能入口、服务、校验、模型配置和持久化。桌面默认模板与行为保持不变。
- 一个宿主持有一份 controller 和草稿，桌面与移动端使用不同呈现；改变窗口尺寸不能重新加载草稿、重复发请求或丢失编辑内容。
- 各功能自行决定列表、详情、表单的合理层级，不强行套统一步骤向导。公共能力限于标题/返回、可滚动正文、键盘避让及主要操作栏。
- 次要操作进入对应条目的菜单；主要操作始终可到达。正文、表单和值优先占空间，不用放大标题或密集图标填充页面。
- Android 返回先退出当前编辑或详情，再回管理列表，最后返回原工作区；未保存内容遵循明确的保存/放弃语义。

## 各业务的移动呈现

| 功能 | 列表与定位 | 详情 / 编辑 | 主要操作与业务复用 |
| --- | --- | --- | --- |
| 模型管理（第一批） | 保留文本、图像、功能模型三个分类；紧凑行展示名称、模型/供应商与启用状态 | 点行直接进入配置，无额外只读详情页；连接信息和模型展开，高级参数/请求头折叠 | 明确的测试与保存；复制、启停、删除在条目菜单。复用文本/图像 manager 与参数编辑能力 |
| 历史记录 | 搜索与模式筛选保留在列表顶部；按优化链呈现，避免所有版本全文展开 | 进入一条链查看版本和正文，版本选择不遮挡正文；恢复前清楚标明目标工作区 | 恢复为主要动作，删除为次要动作；复用已有恢复与草稿保护 |
| 功能提示词 / 模板 | 先按用途显示当前分类及搜索结果，七种模式直接可选，不先切父级再切子级 | 详情优先展示模板正文；编辑进入独立草稿，保留预览和变量说明 | 编辑/保存为主要动作，复制、导入、迁移放入明确菜单；复用原模板服务和校验 |
| 变量管理 | 保留现有手机卡片思路，每行显示变量名和值摘要；长值不撑高整个列表 | 编辑页分别安排名称、说明、值；长文本值占主要空间 | 保存/取消固定可达；导入导出属于列表层，避免编辑弹窗内继续叠弹窗 |
| 收藏 | 复用现有列表、详情、编辑子组件；搜索和常用筛选可见，低频筛选单独展开 | 正文或图像优先，来源、标签等信息折叠；编辑与查看使用同一份条目状态 | 应用到工作区为主动作，编辑、导出、删除为条目动作；保持既有来源关联与资源处理 |
| 数据管理（最后） | 按本地备份、远程备份、恢复、清理分组，避免一页堆叠所有表单 | 进入所选操作后展示其必要配置及范围；进度与错误留在当前任务 | 沿用既有恢复/清理确认，明确影响范围；不因移动适配改变数据格式或远程协议 |

顺序：模型管理 → 历史/模板 → 变量 → 收藏 → 数据管理。先通过一个完整业务闭环，再复用经过真机检验的呈现方式。

## 第一批：模型管理

### 页面与状态

`ModelManager.vue` 继续持有分类和刷新关系。列表页顶部放返回、标题与新增，下方直接显示三个分类。文本和图像条目可复用行容器，但能力标签、测试状态与图片预览通过明确内容区提供，不新建一套统一模型业务类型。

配置页顶部保留返回和模型名称，默认展开连接信息、供应商与模型选择。高级参数和自定义请求头折叠但可发现。供应商较多时使用可搜索选择面板。底部放连接测试与保存，测试中显示状态；失败时保留输入和错误，不能关闭编辑页。

功能模型保留现有评估、识图选择与能力过滤，使用紧凑选择卡，不增加编辑向导。新增模型后应立即出现在符合能力的选项中。

### 代码复用和需要抽取的部分

- `useTextModelManager` 已提供列表、启停、克隆、连接测试、模型刷新、参数及保存能力。由宿主单次创建，供两种呈现共同使用。
- `TextModelManager.vue` 的弹窗开关、删除确认，以及 `TextModelEditModal.vue` 的未保存确认、提交错误和请求头转换仍需明确归属。必要时抽共享编辑 controller，保持桌面模板和既有语义。
- `useImageModelManager` 继续负责字段校验、参数合并、保存与真实图像测试。`ImageModelManager.vue` 持有的逐模型测试状态和预览在返回列表后仍保留。
- 图像编辑当前关闭时直接清草稿，文本编辑有未保存确认。这应作为明确的移动交互修复实现，不能通过重构暗改桌面行为。
- `ModelAdvancedSection`、`ModelParameterEditor` 继续解释和编辑参数，只增加必要的移动呈现参数，不复制参数系统。
- 可增加移动模型列表、编辑壳和操作栏组件；暂不建立覆盖所有管理业务的通用框架。

### 真实手机验收

以 360×669 CSS 视口为主，补 393/430 宽度和桌面原行为。复用现有预览模型，克隆临时测试项，不覆盖用户原配置。

1. 列表定位 → 克隆 → 编辑名称、连接和模型 → 键盘展开时到达末尾字段与保存 → 测试成功 → 保存 → 返回工作区选用该模型 → 完成一次优化与测试。
2. 图像模型同样完成配置、真实生图与完整预览；折叠、返回、切分类不能重复触发生图。
3. 覆盖测试失败、保存失败、继续编辑、放弃修改、Android 返回、切分类后列表位置、窗口宽窄切换与功能模型刷新。
4. 保留密钥遮罩及未修改的原值、供应商切换规则、参数合并、默认模型保护和 `modelsUpdated` 刷新链。自动化只增加这些真实风险对应的测试。

完成上述流程并检查截图后，才将模型管理标记为“已适配”；其他功能逐项使用各自的操作闭环验收。
