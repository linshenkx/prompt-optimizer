# 移动端阶段基线与架构评估

日期：2026-10-22。范围：从 `9141ae9c` 起的移动端工作区变更。

## 结论与完成边界

保留“共享业务能力、移动端重组呈现”的方向。当前实现没有新增移动端服务层、模型调用器或独立持久化体系，适合作为阶段基线提交；还不适合宣称移动端整体设计完成。

七种工作区已接入优化/测试两区、同页编辑与折叠、并排结果、提示词来源查看和手机键盘避让。导航使用紧凑功能面板与一次展示七个子模式的选择面板。模型、模板、历史、收藏、变量、数据等管理功能，目前主要适配了容器、返回和部分操作可达性；内部列表、复杂表单和操作层级仍需逐项设计并在手机验证。

本文是当前架构与范围说明。其他 `mobile-*.md` 及根目录 `design-qa.md` 保留为有日期的阶段记录，其中废弃的区内标签、单结果切换和旧预览环境不能当作现行设计。

## 变更分层

| 层次 | 主要位置 | 对原工程的影响 |
| --- | --- | --- |
| 布局环境 | `useWorkspaceLayout`、`MainLayout` | 统一工作区宽高、1024px 分界、visualViewport 与键盘状态；不按机型或 UA 分支 |
| 临时视图状态 | `useWorkspaceViewState`、`useWorkspacePresentation` | 按七个模式保留区域、折叠及滚动；不混入持久提示词和版本数据 |
| 呈现基础件 | `OptimizeWorkspaceLayout`、`TestWorkspaceLayout`、`WorkspaceRegionSwitch`、`MobileTestResultHeader` | 通过 slots 重组现有内容，保持编辑器挂载；底层模型调用不变 |
| 共享业务组件 | `InputPanel`、`PromptPanel`、`OutputDisplay*`、上下文和图片组件 | 增加 `compact` / `mobileLayout` / `fitContent` 等明确呈现选项，默认保留桌面布局 |
| 导航与覆盖层 | `CompactNavigation`、`AdaptiveModal`、`useCompactModalBack` | 手机功能面板、直接子模式选择、全屏管理容器与 Android 返回；保留既有路由及业务操作 |
| 持久化补充 | 四种文字 session、七工作区测试完成逻辑 | 记录回答实际请求的提示词，图片结果补齐已有 metadata；属于共享数据变更，不能称为纯样式 |
| 开发验收入口 | `vite.workspace-preview.config.ts`、`workspace-preview-models.ts`、初始化器 DEV 分支 | 显式启用的本地同源推理代理和模型预设；与正式产品入口分开说明 |

未修改 `packages/core` 的业务服务、桌面主进程、路由定义、依赖清单或锁文件。共享 UI 包同时供 Web、扩展和桌面 Web 内容使用，因此“没有改桌面包”并不等于没有桌面回归风险。

## 本次整理发现与边界修正

静态检查发现，之前仅验证 1440×900 默认两组结果的几何一致性，不能覆盖所有桌面状态：

1. 基础两模式曾按测试区宽度，在桌面引入单结果标签切换，并放开原有四列限制。整理时恢复桌面原有并排列与限制，手机仍保留全部测试组。
2. 新增草稿覆盖确认和版本切换保护曾作用于桌面。整理时将新增交互限定到移动呈现。
3. 部分样式缺少移动作用域，主框架全端从 `100vh` 改为 `100dvh`。整理时恢复桌面边界。
4. 测试布局只在初始化读取 `view`，后续外部要求展开配置与手动折叠不同步。整理时修复现有受控契约；完整状态命名收敛留待下一步。

以下共享修复和数据补充有意保留，需要独立说明其跨端影响：

- 基础模式迭代失败恢复上一份正文和推理内容，修改要求在失败时保留。
- Markdown 的滚动容器发生替换时，重新填充新容器，防止正文空白。
- 测试结果存储可选 `requestPrompt`，旧会话缺少该字段仍可读取；它记录发送时内容，避免修改当前提示词后错误解释旧回答。图片结果使用已有 metadata，未增加第二种存储格式。

## 架构评估

### 值得保留

- **同一套业务与数据。** 各模式继续调用原有 session、校验、版本、收藏、历史和模型服务，没有复制第二套手机业务。
- **视图状态与业务状态分离。** 区域切换、折叠和滚动不应改变版本、模型选择和测试组数。
- **组件显示选项明确。** 移动呈现通过显式参数启用，工具栏按自身可用宽度折叠，桌面默认分支可单独回归。
- **保持编辑器实例。** 折叠优先使用 `v-show`，减少重新挂载导致的草稿、选择及焦点丢失。
- **统一处理视口和覆盖层。** 手机软键盘与返回语义需要公共能力，不宜散落到每个业务页面。

### 基线审查发现

| 优先级 | 问题及证据 | 建议 |
| --- | --- | --- |
| 高 | `compact-workspace.css` 约 680 行，包含 Naive UI 内部类、`nth-child`、内联 style 字符串选择器及多轮后置覆盖 | 全局只保留 token、视口及覆盖层基础；布局由所属组件的语义类、props、slots 或移动呈现子组件负责 |
| 高 | 基础两模式各自维护滚动捕获/恢复，其余五模式使用 `useCompactWorkspace` | 统一一个视图编排实现，通过明确 ref/方法管理滚动，避免跨层按类名查询内部 DOM |
| 中 | `OptimizeWorkspaceLayout.view`、`WorkspaceSubviewSwitch`、`TestPromptReference` 及旧区内视图状态仍有无调用/失效接口 | 按现行“区域＋折叠＋并排结果”模型清理；把 `useBasicWorkspaceView` 改成覆盖七模式的准确命名 |
| 中 | `useCompactModalBack` 使用模块级栈、直接操作 history、永久 popstate 监听；释放历史等待无取消边界 | 明确生命周期与所有者，补真实 Router 的返回、前进、拒绝关闭和卸载组合测试；保留已验证的手机返回语义 |
| 中 | 请求快照固定了提示词，但部分结果标题仍来自当前来源/模型配置 | 后续统一快照来源、版本、模型元信息及旧结果提示，避免正文正确而标签表达不清 |
| 中 | 预览模型常量和旧配置一次性迁移位于共享 UI 初始化链 | 后续迁到独立开发 bootstrap，网关及模型由开发配置输入，避免业务初始化长期积累机器验收逻辑 |

这些是维护成本和测试缺口，不等于都已复现为故障。阶段基线先修正明确的桌面越界及状态契约问题；后续呈现层整理见下节。覆盖层历史栈、请求元信息和开发 bootstrap 不混入本轮重构。

## 呈现层整理（2026-10-22）

目标是保持现有移动端功能和桌面端行为，清理上一节前三项架构问题。此次不改变模型服务、会话格式、版本业务、路由、依赖及管理功能内部交互。

### 状态与编排归属

- `useWorkspaceViewState` 仅保存七种模式各自的区域、输入折叠、测试配置展开及两区滚动位置。删除已经失去界面对应关系的原文/工作区子页、活动结果标签、每组结果独立滚动和配置页滚动状态。
- `useWorkspacePresentation` 是七个工作区共同的呈现编排入口，负责离开区域前记录位置、切换后恢复位置，以及优化/测试开始时展示对应区域。
- `OptimizeWorkspaceLayout`、`TestWorkspaceLayout` 通过类型化的公开接口提供滚动读写；原文定位由优化布局提供。父级不再查询这些布局的内部 DOM 类名。
- 来源跳转由 `showOptimizationSection` 统一编排：先等待区域恢复，再定位并记录新位置。真机回归发现普通滚动恢复会覆盖来源定位，本轮补齐这一时序约束；离开区域或卸载时取消失效跳转。
- 测试配置使用明确的 `configExpanded` 受控状态。自动空间预算、手动展开、开始运行时折叠保持原有规则；折叠时编辑器仍保持挂载。
- 测试组数仍是业务配置，呈现层只决定排版。并排结果没有独立的“当前结果标签”状态；批量运行后续组不应再次打断用户阅读。

### 样式归属

`compact-workspace.css` 仅作为有序入口，`styles/compact/` 按所属功能组织规则。基础 token、视口与覆盖层规则不承担业务组件内部布局。输入、提示词、输出、上下文、图片、测试结果及管理功能使用各自的语义类，避免按 `nth-child`、内联样式字符串或多层 flex 结构定位。

共享组件继续保留既有桌面默认样式。需要适配 Naive UI 内部结构的规则必须有组件语义根限定，集中在所属模块，不能从全局无边界覆盖。跨组件的窄列比较适配由测试结果模块负责，并在入口中显式排在通用输出/图片规则之后。

### 验证要求

重构前保存了七种模式在 360×669、393×852 手机尺寸下的优化/测试状态，以及 1440×900 桌面状态，共 35 个画面与 DOM 几何记录。验收除比较这些基线外，还应覆盖原文定位、长文末尾、滚动恢复、配置折叠、批量测试、宽窄切换及真实手机键盘。

本轮证据目录为本地 `.codex-run/mobile-architecture-20261022/`，不随仓库发布。

- 35 个状态在对齐正文显示模式后，采样的关键容器位置、尺寸、滚动内容高度、字号和间距全部一致；截图另作人工检查。这是指定状态的几何回归，不代表逐像素或全部产品状态一致。
- 额外检查手机四组按两列展示、800×600 的配置两列排版，以及桌面 1440×900 三列和 2560×1000 四列限制，均符合既有行为。
- 在实际手机 360×669 CSS 视口上检查七种模式：键盘展开后的可视高度约 363px，底部切区栏正确避让；关闭键盘后恢复。两列结果、切区滚动保留与无横向溢出通过。基础系统模式的两列长回答均可读到末行。
- 真机复验来源 B 前往编辑：工作区顶部对齐优化容器顶部；切换测试再返回位置保持。来源跳转与普通区域恢复共享一次恢复过程，不靠父级查询布局 DOM 或增加固定延时。
- 变更相关 20 个测试文件共 134 项通过，其中呈现编排与布局 3 文件 22 项、其余相关 17 文件 112 项。未宣称全量 UI 套件通过。
- UI/Web/扩展类型检查、UI lint、UI 构建及声明生成、Web/扩展构建、语言键一致性与运行时代码中文检查通过。构建保留已有的大包和 Vite 配置提示。
- 本轮复用已有真实优化/测试结果做呈现与状态回归，没有重新发起七种模式的模型推理，未更改用户模型配置。

## 下一阶段的合理结构

```text
已有 services / session / 业务操作与校验
                 │
          各功能共享 controller
                 │
      ┌──────────┴──────────┐
  既有桌面呈现          移动列表 / 详情 / 表单呈现
                            │
             公共 viewport / overlay / 操作栏能力
```

移动业务页面可以有独立的呈现子组件，但不复制模型服务、校验或持久化。先收敛样式和视图状态所有权，再分别设计模型、模板、历史、收藏、变量和数据页面。每页按“列表定位 → 查看详情 → 编辑 → 保存/取消 → 返回原工作区”验收；还要覆盖真实键盘、长文本、运行中和错误状态。

管理功能不能通过单纯切换全屏弹窗来宣布完成。手机验收应判断信息密度、主要操作的层级和正文可读性，而不只是没有横向溢出、按钮能点击。

## 本地预览边界

专用预览从仓库根目录运行：

```sh
pnpm -F @prompt-optimizer/web exec vite --config vite.workspace-preview.config.ts
```

沿用默认端口 18181，监听 `0.0.0.0`。模型预设仅在 `DEV` 且 `VITE_WORKSPACE_PREVIEW=1` 时添加；正常部署不自动写入。真实代理密钥从根目录本地环境的 `MAGPIE_WORKSPACE_PREVIEW_KEY` 读取，不能使用 `VITE_` 前缀暴露给客户端。预览只转发列举的模型目录和推理路径，用户已有同 ID 配置不覆盖。

`.env.local`、浏览器状态、手机设备信息、原始请求与本机验收截图不进入提交。代码中的预览标识不是服务密钥。
