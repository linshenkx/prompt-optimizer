# 工作区更新与跨窗口保存边界

日期：2026-10-23。范围：七种工作区的更新忙碌判定、会话写入和恢复协调。保持现有移动端布局、桌面布局及会话 v1 数据格式。

## 更新忙碌判定

各工作区在原有优化、迭代、测试及生图状态之外，使用评估模块已有的 `evaluation.isAnyEvaluating`。关闭评估面板只是隐藏界面，不能把仍在运行的请求视为空闲。Web/PWA 继续通过原有 `prepareForUpdate` 保存检查点，不另设一份任务状态。

## 存储提交边界

- `IStorageProvider.compareAndSetItem` 为可选能力，只允许真正原子的读、比较、提交。Dexie 使用一次 IndexedDB 读写事务，跨连接串行提交；Memory 使用同步 Map 操作。StorageAdapter 仅传递已有能力，不用普通 get/set 模拟。
- `IPreferenceService.compareAndSet` 负责现有键、序列化和大小限制。没有该能力的提供者继续使用原有 API；Electron 的 IPC/file 存储接口不变。
- 七个 Store 复用 `sessionPersistence` 的读取基线和条件提交。基线按 PreferenceService 实例隔离，只有工作区恢复读取可以建立基线，普通导出或图片清理读取不能更新它。
- 保存时基于实际持久化版本比较，检测另一窗口的更新；同一窗口的连续写入按键排队。图片仍由已有存储服务持久化，不将二进制塞回会话快照。
- 无内容变化的定时保存及 pagehide 不写回旧内容，也不把未编辑窗口标成冲突。比较时忽略顶层 `lastActiveAt`，保留对象键顺序不同及旧 JSON 字符串的兼容性；真正提交仍使用完整读取基线。
- 冲突窗口保留内存草稿并提示复制后刷新，不自动覆盖或丢弃。工作区切换返回不重新加载该冲突快照；刷新页面后读取最新持久化内容。存在未解决冲突时，应用更新检查拒绝刷新。

## 导入、图片与锁顺序

安全上下文中使用同源 Web Locks，锁名 `prompt-optimizer:workspace-persistence`：

1. 普通会话保存持有共享锁，允许不同窗口独立准备保存，最终由原子比较决定能否提交。
2. 导入恢复持有独占锁，等待其他窗口的在途会话保存结束。原有页面内冻结继续保护本窗口的 Store。
3. 自动图片 GC 也持有独占锁，避免清掉其他窗口刚写入、尚未提交快照引用的图片。
4. 一律先取浏览器锁、再进入页面内图片维护队列，避免锁顺序相反导致等待环。

恢复租约的排队申请可取消，失败释放全部保护。成功导入后释放同源独占锁，让其他窗口继续运行；导入窗口的旧 Store 和 GC 仍冻结，直到现有刷新流程重新载入。

普通局域网 HTTP 可能没有 Web Locks。IndexedDB 的条件提交仍有效；此时延后自动孤立图片清理，保留可能正在被另一窗口导入的图片。显式图片管理仍可使用。不能用页面内锁或 localStorage 标志冒充跨窗口互斥。

工作区导入自身也进行条件提交；失败回滚仅在值仍等于本次导入结果时执行，避免回滚覆盖另一窗口后来保存的内容。这不是收藏、模型、历史、图片等所有数据的全局原子事务，既有业务部分导入语义不变。

## 损坏快照的条件清理

- 可选的 `IPreferenceService.readSnapshot` 将一次读取与一次性条件删除绑定。原始存储值留在闭包内，不暴露给工作区；超大内容在解析之前拒绝，读取 IO 失败不产生删除凭据。
- Manager 按服务实例和工作区键合并在途恢复，`readSessionSnapshot` 将读取凭据绑定到这次恢复。清理只处理本工作区的已识别损坏错误，不允许错误参数指定其他工作区。
- 清理复用保存的共享锁、导入冻结和同键提交队列，排队后再次检查冻结。只有存储内容仍等于恢复时读到的值，才删除并建立空基线；若内容已被更新，保留当前存储和原有写入基线，不能随后用默认 Store 覆盖新内容。
- 恢复结束释放凭据，后续恢复重新读取；无原子能力的 Electron IPC 提供者保持原有清理路径，不用普通读取和删除模拟原子操作。

## 移动端延后保存

- 移动端自动保存只排队发生变化的工作区键，不复制内容，仍由七个现有 Store 保存当前状态。切换期间延后的编辑不会被保存到后来激活的模式。
- 原有布尔保存接口保持不变；额外的状态接口区分已保存、暂时忙碌、保护阻止和失败。暂时忙碌保留待保存键，等切换或在途保存结束后补存；导入冻结、跨窗口冲突和失败不进入自动重试循环。
- 保留 750ms 防抖和 5s 最长等待。写入期间的新编辑会在之后补存；停用移动布局或卸载取消待执行任务，迟到的异步结果不能重新激活旧任务。桌面端不启用这项订阅。

## 日常 CI 入口

`test:gate` 纳入 Web/PWA 单元测试和偏好存储的原子提交、读取快照回归；`test:gate:e2e` 保留原有 UI smoke/VCR replay，并加入不依赖真实模型的工作区回归组。新增组覆盖七工作区的来源预览、分栏/测试组绑定和手机、桌面双窗口冲突。脚本测试同时校验分组文件和工作流入口，避免测试存在但 CI 没有执行。

## 回归覆盖

- 实际评估请求运行时关闭面板，更新仍返回 busy；请求结束后可保存并返回 ready。
- 两个独立 Dexie 连接在同一 IndexedDB 上并发提交，只有一个读取基线能够成功，旧基线不能覆盖结果。
- 七种真实 Pinia Store 的双窗口保存：较新持久化结果和冲突本地草稿都保留，未编辑窗口保存不误报，切换返回不丢草稿。
- 同窗口连续保存、旧字符串快照、缺失键及旧 JSON null、无原子能力的提供者兼容。
- 导入中发生竞争、导入失败后的回滚竞争、恢复锁取消及成功后的释放、跨窗口保存/导入与图片清理互斥、无 Web Locks 的安全退让。
- Chromium 的手机和桌面视口各两个同源页面：经实际输入和 pagehide 保存产生竞争，检查提示、持久化胜出内容、切换返回草稿以及主动刷新后的最新内容。
