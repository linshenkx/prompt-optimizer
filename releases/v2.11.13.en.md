# Prompt Optimizer v2.11.13

## Summary
- Update build, CI, and Docker Node.js to 24.22.1 for the October 21 security release.
- Upgrade vulnerable application and build dependencies, including Markdown rendering, sanitization, MCP, Vite, and the desktop runtime.
- Electron 44.9.3 still embeds Node.js 24.22.0. The desktop app therefore remains pending an upstream Electron release containing the October 21 Node.js fixes.

## Highlights
- Rebuild container images with patched Node.js in both build and runtime stages.
- Resolve all npm advisories reported for the main workspace and the standalone website lockfiles on October 22, 2026. This audit does not cover vulnerabilities in Electron's embedded Node.js runtime.

## Product Updates
### Desktop
- Upgrade Electron from 41.10.7 to 44.9.3 and update the model-request HTTP client.
### Web and Extension
- Update DOMPurify and markdown-it used for rendered content.
### Core/Infra
- Update MCP SDK, Vite, Vitest, and vulnerable transitive packages. Update the website's separate dependency lockfile as well.
- Require Node.js 24.22.1 or a newer Node.js 24 patch for development and builds.

## Fixes
- Remove vulnerable legacy desktop download dependencies by using the current Electron downloader in electron-builder.
- Upgrade dependencies affected by proxy address parsing, command quoting, selector parsing, archive pattern handling, and MCP advisories.

## Breaking Changes / Upgrade Notes
- No user-data migration is required.
- Self-hosted Docker users must pull the new image and recreate their containers; updating Node.js on the host does not update an existing container.
- Desktop users should install this maintenance release for the available Electron and dependency fixes, but must not treat it as a complete fix for the October 21 Node.js vulnerabilities. Follow-up desktop remediation requires an upstream Electron release with those patches.
- Vercel manages Node.js patch versions. Selecting Node.js 24 alone is insufficient evidence of the exact runtime patch.
- On October 22, the checked Vercel production deployment still reported Node.js 24.21.0 after redeployment. The managed function runtime remains pending Vercel's patch rollout; the project's version setting cannot force a specific patch.

## Developer Notes
- Pin local and CI Node.js using `.node-version`; pin both Docker stages to 24.22.1.
- Record runtime versions in server and desktop startup logs for deployment verification.
- Keep targeted transitive overrides until upstream dependencies adopt their patched versions.
