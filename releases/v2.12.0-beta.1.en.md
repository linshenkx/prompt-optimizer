# Prompt Optimizer v2.12.0-beta.1

## Summary
- This first mobile and PWA preview is for users who want to try the new workflows on their own devices. The stable release channel remains separate.
- Add mobile layouts across seven workspaces, organized around Optimize and Test, with prompt context and side-by-side results.
- Adapt model, history, template, variable, favorite and data management to phone-sized lists, details and forms.
- Add an installable production Web PWA with offline access to saved local work and save-before-update controls, backed by stronger workspace recovery and cross-window write protection.

## Highlights
- View original and optimized prompts in one region. Configuration and toolbars adapt to available space, reducing nested tab switching and leaving more room for content.
- Inspect the prompt source while testing and compare results together, with improved long-text reading, image previews and keyboard-aware controls.
- Reuse existing business components and data services. Wide desktop layouts retain their established split views and interaction patterns.

## Product Updates
### Web
- Cover Basic System, Basic User, Context Multi-message, Context Variables, Text-to-image, Image-to-image and Multi-image workspaces.
- Reorganize mobile navigation and mode selection so specific modes are visible together and navigation happens after a concrete selection. Management views support list, detail, edit and return flows.
- Improve phone workflows for model forms, history restoration, template editing, variable imports, favorite categories and tags, and data import/export.
- Add installation guidance, standalone presentation, offline status and Save and update. Active generation or evaluation, unsaved management forms and save failures block updates; other open windows in the worker's scope must be closed before retrying.
### Core/Infra
- Include seven workspace snapshot types and associated images in backup/restore, supporting address changes through the existing export/import flow.
- Strengthen conditional workspace writes, conditional cleanup of damaged snapshots, image-cleanup coordination and deferred mobile saves to prevent stale windows from overwriting newer content.

## Fixes
- Avoid false Save and update conflicts when another window has only initialized default values, while retaining protection for actual concurrent edits.
- Keep updates blocked while evaluation requests are active, including after their panel closes.
- Retain deferred mobile saves after temporary busy states, and include the latest message input when saving immediately after editing.
- Fix keyboard-obscured selection menus, configuration collapsing during editing, and model settings being cleared when reselecting the current provider on mobile.
- Improve access to the end of long output, toolbar density, image comparison and scrolling inside mobile dialogs.
- Restore the previous prompt when an iteration fails.
- Correct Docker public-asset cache policy and Manifest MIME handling so eligible deployments can install the PWA, while continuing to protect configuration, APIs, authenticated responses and errors.

## Breaking Changes / Upgrade Notes
- Existing access methods and desktop interactions remain available; no manual workspace data conversion is required. Adding a mobile evaluation interface is outside this release's scope.
- PWA installation requires a production Web build on trusted HTTPS or browser-trusted localhost. Plain LAN HTTP IP addresses remain usable online but cannot provide full PWA installation.
- Android Chrome offers browser installation controls; iOS Safari uses Share → Add to Home Screen. Device acceptance for this release covers Android; iOS device acceptance has not been completed.
- Offline support opens, reads and edits previously saved local work. Model inference, first-time loading and online configuration retrieval still require connectivity. This is not a native APK or an offline model runtime.
- Docker deployments using `ACCESS_PASSWORD` retain authentication and online access, but do not support offline-shell installation. Do not expose protected entry documents to enable installation.
- Browser data is isolated by origin. Changing the domain, protocol or port does not automatically migrate data. Export a resource-complete backup before moving to HTTPS, then import it at the new address.
- Finish active tasks, resolve unsaved forms and close other windows of the same application before choosing Save and update. Preserve local drafts when a real conflict is reported rather than forcing an overwrite.
- Development HMR, Electron and browser extensions do not register this Service Worker. Reverse proxies must preserve the public-asset/private-runtime cache boundary.

## Developer Notes
- Preview releases build application artifacts and Docker images through one Release workflow using the same version and source commit. Preview images use explicit version tags and do not update stable latest aliases.
- Mobile presentation and style ownership are explicit. Shared workspace helpers handle split views, test bindings, source previews and batch operations; model-specific and business-specific decisions remain with each mode.
- PWA code lives in the Web package and calls a shared UI update-preparation interface rather than accessing internal workspace stores directly.
- Existing CI gates now cover Web/PWA behavior, conditional persistence, damaged-snapshot cleanup, deferred saves, mobile/desktop behavior across seven workspaces, and Docker HTTP policy.
- The local model-preview gateway is an opt-in development tool. Production builds do not include the test Magpie service or free-model credentials.
- See [PWA technical guidance](../packages/web/PWA.md) and [Docker deployment guidance](../mkdocs/docs/en/deployment/docker-basic.md) for installation and caching boundaries.
