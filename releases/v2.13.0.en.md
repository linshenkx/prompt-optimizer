# Prompt Optimizer v2.13.0

## Summary

This stable release brings interactive HTML inside Markdown results to Web, Desktop and the browser extension, with a redesigned output pipeline for concurrent generation and large responses. It also improves backup integrity, adds import codes for selected cloud backups, preserves model selections and saved parameters, and refines image-editing and structured-input templates.

## Highlights

- **Interactive output in place:** use Preview or Source to inspect results. Explicit HTML code blocks and supported HTML content render as isolated web pages alongside the surrounding Markdown. Multiple blocks can remain interactive at the same time.
- **Interactive extension previews:** fix the beta's extension script restriction so generated buttons, forms and canvases work inside results without opening another tab.
- **Bounded streaming and rendering:** generation uses a dedicated output document, virtualized source views and background Markdown parsing. Oversized or expensive content falls back to source.
- **More reliable backups:** validate data and image resources before restoration, protect existing images from eviction, and restore workspace snapshots only after preceding import steps succeed.
- **Cloud backup import codes:** transfer a selected WebDAV, S3-compatible or Cloudflare R2 snapshot using a code, link or QR code when its size permits.

## Product Updates

### Desktop

- Propagate cancellation from the interface through desktop IPC to model requests. Streaming completion now waits for asynchronous completion work.
- Use the shared Preview/Source output interface, inline HTML previews and backup import-code flow.

### Web

- Render multiple HTML examples directly in Markdown results. Switching one result to Source leaves other results' previews intact.
- Keep in-progress responses in the source view; executable previews are created after generation completes.
- Allow HTML previews to request external data while retaining isolation from the application. Requests remain subject to browser CORS rules and the target service's authorization requirements.

### Extension

- Display and run multiple HTML blocks inside results, including inline scripts, event handlers, external script libraries and modules.
- Allow external API requests while preventing preview pages from reading the main application, its storage or extension APIs. Keep the main extension pages' existing content security policy.
- Support Preview/Source switching, content replacement and fullscreen viewing. Release preview pages when their corresponding results are removed.

### Core/Infra

- Separate streaming text from reactive workspace snapshots and publish final or interrupted results at explicit completion boundaries.
- Apply output-size, rendering and queue budgets, and cancel obsolete parsing work.
- Carry cancellation signals through OpenAI-compatible, Anthropic and Gemini streaming adapters.

## Fixes

- Resolve extension content security policy restrictions that blocked preview scripts, and reject forged content updates from preview child pages.
- Preview standalone HTML controls such as buttons, and keep output-toolbar actions within narrow mobile comparison columns.
- Reject invalid backup sections, conflicting image resources and insufficient image-storage capacity before publishing new references. Report partial restoration and rollback failures explicitly.
- Preserve relevant settings and image references across export and import. Keep workspace restoration as the final import step.
- Preserve model selections when refreshing lists, including empty responses and fallback lists. Retain saved parameters when provider definitions change while validating edited values against applicable definitions.
- Clarify reference-image roles, edit scope and preservation requirements in image templates. Keep structured JSON fields, types, control values and placeholders intact.
- Update Zod, body-parser, qs and the build tooling's Undici 6 dependency to patched versions for previously identified security advisories.

## Breaking Changes / Upgrade Notes

- This upgrade changes backup restoration and output processing. Export a backup of important workspaces before upgrading.
- Cloud backup import codes contain storage credentials; they are not restricted public sharing links. Give them only to trusted recipients. Google Drive backup import codes are not supported in this release.
- HTML scripts run in isolated iframes. Isolation protects the main document and restricts permissions, but does not impose hard CPU or memory quotas on arbitrary generated scripts. WebGPU availability still depends on the browser and device.
- Exceeding output or rendering budgets may stop generation or switch to source display. Interrupted and normally completed results remain distinct.
- The extension ZIP uses numeric version `2.13.0` without the beta display name. Replace manually installed `2.13.0-beta.1` packages manually. The release workflow does not automatically submit to browser extension stores.
- Stable Docker images use `2.13.0` and `latest` tags. The GitHub Release is published as stable and is available to the desktop stable update channel.
- The build-only deepmerge dependency still has an unpatched low-severity advisory; the identified path merges trusted Rollup configuration and is not part of the application runtime.

## Developer Notes

- The output pipeline uses bounded documents, CodeMirror source views, a shared Markdown Worker and isolated iframes. See the [output architecture](https://github.com/linshenkx/prompt-optimizer/blob/v2.13.0/docs/architecture/output-pipeline.md).
- The extension uses a manifest-declared sandbox page as its preview host; Web and Desktop retain their existing srcdoc path.
- The daily browser gate now builds the real extension, scans for sensitive configuration and loads it with an isolated browser profile. Coverage includes multiple interactive blocks, external resources, permission isolation, source fidelity, concurrent producers and CPU throttling.
- CPU throttling is simulated. Extension tests use page freeze/resume and visibility events; these do not constitute complete acceptance on low-end hardware or under native background-tab throttling.
- The release workflow validates tags and application versions, runs test gates and packages Desktop and the extension. It publishes the stable Release only after validating multi-architecture Docker images and latest tags in both registries.
