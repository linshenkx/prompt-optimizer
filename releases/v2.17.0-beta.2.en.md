# Prompt Optimizer v2.17.0-beta.2

## Summary

This preview migrates desktop structured storage to local SQLite in WAL mode, automatically and atomically importing data from `prompt-optimizer-data.json` on first launch while keeping legacy JSON files untouched as pre-upgrade snapshots. It also hardens desktop quit and startup error handling and fixes concurrency edge cases across history, templates, preferences, and IndexedDB storage.

## Highlights

- **Atomic SQLite desktop storage:** Replace full-file debounced JSON rewrites with short SQLite WAL transactions backed by `node:sqlite`, preserving all models, image model configs, templates, history chains, contexts, favorites, preferences, variables, and workspace drafts.
- **Zero-touch legacy preservation:** First-run startup copies `prompt-optimizer-data.json` (or an existing `.backup` if needed) into `prompt-optimizer-data.sqlite` in one transaction without modifying, deleting, or rewriting the original JSON snapshot.
- **Clear startup and shutdown protection:** Startup prevents silent overwrites when SQLite fails to initialize (distinguishing storage, WAL-unsupported, and service errors with an action to open the data directory), and app quit drains pending SQLite closes safely across repeated quit events.
- **Cross-store concurrency reliability:** History iteration appends, template mutations, preference clearing, and browser IndexedDB queued updates serialize cleanly without losing updates, breaking chain roots, or masking domain errors.

## Product Updates

### Desktop

- Switch desktop structured storage (`models`, `templates`, `history`, `contexts`, `favorites`, `preferences`, and drafts) from `FileStorageProvider` (`prompt-optimizer-data.json`) to `SQLiteStorageProvider` (`prompt-optimizer-data.sqlite` with SQLite WAL mode) via `@prompt-optimizer/core/node`.
- Run an atomic one-time migration on the first launch with no completed migration marker. Keep the original `prompt-optimizer-data.json` and any existing `.backup` on disk.
- Serialize `will-quit` storage closing across secondary quit attempts, close opened storage cleanly on fatal startup failure, and reset updater quit locks when auto-update errors occur.
- Present localized startup error dialogs (`zh-CN`, `zh-TW`, `en-US`) for WAL-unsupported filesystems, storage initialization failures, and post-storage service initialization failures, surfacing directory-open errors explicitly.

### Web

- No user-facing Web workflow or UI changes in this release. Underlying IndexedDB `updateData` concurrency and domain-error handling in `DexieStorageProvider` are improved cleanly.

### Extension

- No extension-specific user-facing changes in this release. Built artifacts remain isolated from Node SQLite modules.

### Core/Infra

- Expose `@prompt-optimizer/core/node` (`SQLiteStorageProvider`, `openDesktopStorage`, `openExistingDesktopStorage`, `openExistingDesktopStorageForWriting`, `exportDesktopStorageAsLegacyJSON`) as a Node-only entrypoint separate from `@prompt-optimizer/core`.
- Convert `HistoryManager` mutations (`deleteRecord`, `deleteChain`, `addIteration`), `TemplateManager` saves/deletes, and `PreferenceService.clear()` (via atomic `deleteByPrefix`) to single-transaction operations.
- Add `trimRecordsPreservingRoots` across history additions, iterations, and imports to preserve active chain roots and re-link `previousId` ancestors within the 50-record limit.
- Normalize unpaired UTF-16 surrogates to `U+FFFD` during raw SQLite writes and legacy migrations (rolling back if normalized legacy keys collide) while keeping JSON-escaped text intact.

## Fixes

- Prevent concurrent `HistoryManager.addIteration` calls from forking linear chains or losing updates against deleted chains, and keep returned chains consistent with the 50-record retention cap.
- Keep `getChain`, `getAllChains`, and `getIterationChain` consistent across 50-record trimming and history imports in newest-first order.
- Ensure `PreferenceService.clear()` deletes all persisted preferences including untouched or cross-connection keys atomically without partially tearing concurrent batch writes.
- Preserve synchronous modifier domain errors (such as `RecordNotFoundError`) across `DexieStorageProvider.updateData` instead of retrying or wrapping them into `StorageError`, and isolate per-key FIFO queues so a rejected mutation does not fail subsequent queued updates.
- Restore `createDesktopServiceBridge` main-process slicing boundaries alongside lifecycle helpers in `packages/desktop/main.js`, and gate SQLite `birthtimeNs` identity checks to `win32` and `darwin`.

## Breaking Changes / Upgrade Notes

- This prerelease previews the desktop SQLite storage upgrade. Back up important data with the app's backup or export tools before upgrading.
- After upgrading, new desktop edits are written to `prompt-optimizer-data.sqlite` in the user data directory; the existing `prompt-optimizer-data.json` remains intact as a pre-upgrade snapshot and is not updated afterwards or re-read on future startups.
- SQLite WAL mode requires the desktop data directory to reside on a local disk volume supporting file locking (certain network/virtual filesystems are rejected cleanly on startup without modifying files).
- Browser and desktop IndexedDB image stores (`PromptOptimizerImageDB`, `PromptOptimizerFavoriteImageDB`) remain unchanged in this release.
- The extension ZIP is available for manual installation. Its numeric version is `2.17.0` and its display version is `2.17.0-beta.2`.
- Docker images are available under the preview tag `2.17.0-beta.2`.
